### 19.2 唯一不一致项：混沌金附魔书的两条对角线（改了什么）

| 项 | 改前（轮4 落地，旧口径） | 改后（作者 2026-10-17 口述） |
|---|---|---|
| `pattern` | `LIL` / `IBI` / `SIS` | **`LIS` / `IBI` / `SIL`** |
| 青金石（`minecraft:lapis_lazuli`） | 左上 + 右上（同一行两端） | **左上 + 右下（主对角）** |
| 混沌金币串（`bettergold:chaos_coin_string`） | 左下 + 右下（同一行两端） | **右上 + 左下（副对角）** |
| 混沌金锭 / 书 | 中上·中下·中左·中右 / 中间 | **不变** |
| 产物 / 数量 | `bettergold:chaosgold_enchanting_book` × 1 | **不变** |

**只改了 `pattern` 两行字符串**（`"LIL"→"LIS"`、`"SIS"→"SIL"`；文件仍 **445 B**，其余字节逐个不变；SHA256 见 §19.7）。

**为什么旧口径会是那样（诚实记账）**：轮4 的实现是在"计数逐项与派单一致"这个判据下落的
（2 青金石 / 4 锭 / 1 书 / 2 币串，见 §13.4），**计数对了但位置反了**；而当时的关卡
`bgn10r4-enchanting-book` 把产物的 `LIL/IBI/SIS` 连同文案"截图读出的 LIL/IBI/SIS"一起当成了
契约 ⇒ **关卡把错的那一版钉住了**。立档 §2.6 自己写的"100% 读出"从一开始就是
`青金石/锭/币串 · 锭/书/锭 · 币串/锭/青金石` ⇒ 旧实现**违反了自己的立档**，
而这条矛盾三轮都没被抓住，原因是**没有"逐格"这个维度的断言** ⇒ 本轮正把这个维度补上（§19.4）。

### 19.4 关卡：新增 `[bgn10rc-*]`（四类配方**逐格**）

`tools/asset-generator/validate_metal_data.py` 新增一段（插在 `_EXIT_PROBLEM_LISTS` 之前，
并入退出码元组），判据（每条都能单独变红）：

| tag | 钉什么 |
|---|---|
| `bgn10rc-id` / `bgn10rc-file` | 配方文件名是**稳定 ASCII**（`[a-z0-9_]+`）+ 4 个文件都在 |
| `bgn10rc-type` | 三条充数 = `crafting_shapeless`；模板 / 附魔书 / 砧 = `crafting_shaped` |
| `bgn10rc-filler` | 每条充数：材料总数 = N+1、锭 = N、**混沌金币恰好 1 枚**、产物 = 1 个对应方块、**不许混进第三种材料** |
| `bgn10rc-cell` | 模板 / 附魔书 / 砧的 **9 格逐格**（点名"第几行第几列"，整张表附在失败文案里） |
| `bgn10rc-book-lapis` / `bgn10rc-book-coin` | 附魔书里必须有 `minecraft:lapis_lazuli`；**不许**出现 `bettergold:chaos_coin`（币串 ≠ 币） |
| `bgn10rc-result` | 三条 shaped 的产物 id |
| `bgn10rc-generator` | 把 `generate_chaosalloy_recipes.py` 当模块加载 → `TEMPLATE_PATTERN == GIG/GAG/GCG` + **它自己的 `check()`** + **20 份产物与真源逐字节一致** |
| `bgn10rc-doc` | 本节（`bg-n10rc` + 4 句作者原话逐字）必须落档 |
| `bgn10rc-anti-vacuum` | 本段判定数 ≥ 40（反空转） |

**旧期望就地留档**：`bgn10r4-enchanting-book` 那条的 `["LIL", "IBI", "SIS"]` 与文案
"截图读出的 LIL/IBI/SIS" **原文保留在注释里**（未删、未放宽）；新期望 = `["LIS", "IBI", "SIL"]`。
