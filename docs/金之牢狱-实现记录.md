## 1. 六步逐段

### 第 1 步：抠 14 件 + 造 9 种造型（①的落地）

**做了什么**（`docs\金之牢狱-实现-证据\gp_build.py --stage 1`）：

- 复用上一轮的自写 NBT/.mca 解析器（`nbt.py` 原样复制，SHA256 `CE5FFE98…`），把存档里 14 个件的方块**逐格读进内存**（键 = 相对坐标，值 = `[方块 id, 属性字典]`）。
- **变体 B = 南北轴镜像**（`x → sx−1−x`）：属性按面翻（`facing` 东西互换、`east/west` 两个布尔互换（含"只有一边为 true"的墙/栅栏/玻璃板）、楼梯 `shape` 的 `inner/outer_left ↔ right`，`axis`/`age`/`moisture`/`half` 不动）。
- **变体 C = 丰饶版**：在 A 件**内部**挑一块「全部可站、且不与过道口列冲突」的最大矩形（small 2×3 / medium 3×3 / large 3×3），
  把地面换成 `gold_infused_farmland`、上面种 `golden_wheat_crop` / `golden_carrot_crop` / `golden_eggplant_crop`、
  放 2 个 `golden_toad_figurine`、**最远那一格放箱子**（不挡道）。**所有方块与属性都从 P02 中央农田 / P03 金蟾与箱子原样搬**（含 crop 的 `age`、farmland 的 `moisture`、chest 的 `facing/type`），**没有自己造任何新造型**。
- 自检：镜像件「镜像两次 == 原件」；镜像后块数/调色板/口位三重相等；丰饶版**只动了 `1 ≤ x ≤ sx−2`、`1 ≤ z ≤ sz−2`、`y ∈ {walk_y−1, walk_y}`**（外壳、屋顶、过道口列**一格未动**），且必然有箱子、必然有作物、调色板不越界（只允许新增 farmland/三种作物/金蟾/箱子）。

### 第 2 步：注 Jigsaw（20 件 / 42 个口）

**做了什么**（`--stage 2`）：每个口在**洞口那一格**（边界层、口底正中）放 `minecraft:jigsaw`——
`orientation = <外侧>_up`、`name/target/pool` 按下面的接线表；块实体另带 `final_state=minecraft:air`、`joint=aligned`、
`placement_priority=0`、`selection_priority=0`。⚠ **不是"内侧一格"**：引擎的对齐公式是
`B.origin = A.origin + 父口 + D − 子口`，jigsaw 必须落在**件自己的边界格**上，子件才会"面贴面"；放进内侧一格会让子件**插进父件内部**并被碰撞检查拒绝（关卡 `[bgp-gate]` 的 ①② 就是照这个写的）。

> ⚠ **第四轮（2026-10-21）就地标注**：下表是**第一轮**的接线，**已被 §11.2 取代**（15 池 → 4 池、小牢房链删除、过道对称、exit 的 target=empty）。原文保留。

**为什么小牢房是三步循环**：三个小牢房变体的**两个口同名同目标**（同构），所以引擎无论挑哪个旋转、
父件从哪一头接进来，**剩下来的那个口**都指向下一步 ⇒ `A → 镜像 → 丰饶 → 回房间`，一次连出来的小牢房恰好 3 件且必含丰饶版。
`cell_small_1/2/3` 三个池的 `fallback` 都指向**自己**，所以即使 `size` 在链子中间截断，下一步也照样会补齐（不会留下一截断头）。

**读数**：20 件共 **42 个 jigsaw**（宝藏 1 / 四面道各 4 / 12 个牢房各 2 / 过道 2 / 出入口 1）；每件的口集合与 §3.5 表一致；每件 jigsaw 数量 == 口数（自检直接读 NBT 数）。

**遗留**：`lane` 的两个口**故意不对称**（北回房间、南进小牢房链）——这是"三步循环"唯一可行的接线方式（`canAttach` 只认"父 target == 子 name"的单向匹配）。代价：引擎在两个等价旋转里随机挑一个，所以约一半的过道通向小牢房链、一半通向普通房间。**这一点已记账，作者觉得"过道一半都通小牢房"太多的话，最小改法是给 `lane` 池加第二个变体（两条口都通房间的过道）并按权重配比。**

### 第 3 步：导出 `.nbt` + 俯视蓝图

**做了什么**（`--stage 3`）：自写 NBT writer（`DataVersion=3955`、`size` / `palette` / `blocks` / `entities` 四个根键，1.21 路径 **`data/bettergold/structure/`**，不是 `structures/`）；
箱子的块实体写 `LootTable = bettergold:chests/golden_prison`（**逐箱写**：20 个模板里一共 **23 个箱子**，来源 = 作者原件的 14 个 + 3 个镜像件各 1 个 + 3 个丰饶件各 2 个）。
gzip 用 `mtime=0` ⇒ **字节可复现**（连跑两次 SHA 相同，已实测）。

**逐格自检**：每个 `.nbt` 写完后**重新解析**，把方块集（坐标 → id + 属性）与第 2 步的内存件**逐格比对**，不一致就 `SystemExit`。20/20 通过。

**蓝图**：`docs\金之牢狱-蓝图\` 20 张 PNG + `README.md` 索引。每张是**可行走面那一层（walk_y）的平面图**：
绿 = 能站的空气、金 = 作者原有金方块、洋红 `J` = jigsaw 口位、`C` = 箱子、`S` = 刷怪笼，带 **N/S/E/W** 与每 5 格一条坐标刻度（原点 = 结构框西北角）。

**读数**：20 个 `.nbt` 共 **33,117 个方块条目**（含 42 个 jigsaw），文件 484 B ~ 20.8 KB。逐件尺寸/方块数/SHA256 见 §8 与 `nbt_manifest.json`。

**遗留**：蓝图的"可站"判据是**几何**（该格 air + 下面一格实心），不判"玩家真的走得到"；真正的连通性由第 6 步 A 级的**逐格 junction 检查**兜。

**口径记账（我拍的）**：
- **`size = 6`**：沿一条路 = 宝藏(0) → 过道(1) → 房间(2) → 过道(3) → 房间(4) → 过道(5) → 房间(6) → **出入口(7)** ⇒ 一条路 **3 段房间 + 3 段过道**（满足"至少 2–3 段房间"）。`size` 是**偶数是刻意的**：偶数值让最深那件是"房间"，它的口 target=lane ⇒ 走到 `lane` 池的 fallback ⇒ **每条分支末端正好一个出入口**。
- **`spacing=32` / `separation=16`**（chunk）：结构最大跨约 143 格（A 级实测 bbox 143×34×128），32 chunk = 512 格，够散开。
  > ⚠ **第三轮（2026-10-20）就地标注**：已按作者要求改成 **27 / 4**（= 下界要塞），见 §10.3；原值保留。
- **`max_distance_from_center=100`**：`terrain_adaptation != none` 时 `max_distance_from_center + 12 ≤ 128`（`JigsawStructure.verifyRange`），100+12=112 ✓。
- **出入口的 `target`**：作者原话只到"出入口是终点"。**我给它 `target=room` + 引用 `room` 池**——因为它的口是"被父件接上"的那一头，`target` 只在"它自己被展开"时才用到；给它 `room` 可以避免 `minecraft:empty` 池的 `Empty or non-existent pool` 警告，同时**不会**真的继续长（它只在 `depth == maxDepth` 时被放，`depth+1 > maxDepth` ⇒ 不再展开）。侧证：A 级里 34 个口**全部成对**、0 个"落单"，出口没有多长东西。
- **中/大牢房不做三步循环**：它们的三个造型**权重随机**（`room` 池里按权重 roll），因为作者只对"三件连一起的小牢房"提出固定要求。

**遗留**：`cell_medium_*` / `cell_large_*` / `cross_a` / `cross_b` 这四个（组）池**没有被任何 socket 引用**——它们的件已经通过 `room` 池参与生成。保留它们是为了让"一个变体一个池"的目录结构完整、方便作者以后单独调某一个变体的权重；如果作者觉得多余，删掉 6 个文件不影响生成。

### 12.3 ★ ③ 丰饶权重 6 → 10

- 改动：`room` 池里 **三条** `*_fertile` 元素的权重 6 → **10**（其余不变）。
- **数学值（按文件里实际的权重算）**：4 个普通变体 2×4 = 8 + fertile 10 = 18/尺寸、三尺寸 **54**；
  + `cross_a` 5 + `cross_b` 5 ⇒ **总权重 64**，非丰饶 = 24 + 10 = **34**。
  - 一次 room 抽到丰饶 = 30/64 = **46.875%**（旧 18/52 = 34.6%）
  - **P(连续 3 个 room 至少一个丰饶) = 1 − (34/64)³ = 0.8501 = 85.0%**（旧 1 − (34/52)³ = 72.0%）
- ⚠ **任务书的记账与文件不一致**（原文留档，不删）：「fertile 6 → 10 ⇒ 新总权重 = **56** ⇒ 1−(46/56)³ ≈ **82.x%**」。
  `56 = 52 + 4`、`46 = 52 − 6` 是按**一条** fertile 元素记的账，而 room 池里 fertile 有**三条**（小/中/大各一条）；
  且 `1−(46/56)³ = 44.6%`（**比旧值更低**），与"要更高"的意图相反。
  本轮按**文件实际**记账（64 / 34 / 85.0%），关卡 `[bgp-pool-reach]` 钉死 64 / 30 / ≥0.80。
  若要精确落在 82%，权重应是 **9**（1−(34/61)³ = 82.7%）。
- **A 级（10 个种子各 1 座，`gph_final`）**：含至少 1 个 fertile 件的座数 = **8 / 10 = 80%**；
  fertile 件占 room 件 = **14 / 44 = 31.8%**。⚠ **样本不足**：10 座里 44 个 room 件⇒单次命中率的
  标准误约 ±7 个百分点，**以数学值 85.0% 为准**，实测只作"没有反向"的旁证（旧配置同口径是 72%）。

### 15.3 算法（每座结构、每个出入口件各一次）

1. **认件**：尺寸 == `exit` 模板（5×8×5）+ **恰好 1 个口且 `target=empty`**（26 件里只有 exit 这样）；
   `afterPlace` 每区块调一次 ⇒ `WeakHashMap` 幂等 + "本区块里那些格子还是不是出入口自己的方块"二次校验。
2. **连通性前置**（父代理 2026-10-22 追加）：以**父件口位外侧那一格**（= 出入口自己的口位格 M，放置后是 air，
   因为 `final_state=minecraft:air`）为种子做 **air-only 洪泛**，且把"搬迁后会被恢复成石头"的旧 footprint 格全挡住
   ⇒ 得到"可达空气集 R"。**目的地必须整块落在 R 里** —— 这就是"黄色已经延伸到空域"的机器判据。
3. **穷举搜索**：把 R 做成 **3D 前缀和**，窗口内任一 bbox 都能 **O(1)** 判"整块都在 R 里"，
   按"离原位多远"从近到远取；**严格档**额外要求 `bbox.inflatedBy(1)` 也在 R 里（＝不贴岩壁），
   退让档只看 bbox 内部（两档都满足 `overwroteNatural == 0`，读数分开报）。
   过去两版被否掉的写法与实测见 **15.4**。
4. **三道闸门**（每次只对最近的 ≤48 个候选跑）：① 新口位格从 M 可达；② 新口位的**朝外一格是空气**
   （否则玩家进不去）；③ 目的地 bbox 不压别的件的 bbox、也不压别的出入口的门道格（件是逐区块放的，
   后放的件会把门口盖掉 —— 实测踩过一次）。
5. **落地**：① 先撤掉旧位置的实体（出入口自带的 2 个展示框）→ `pep.move()` + `pep.place()` 在新位置重放；
   ② 恢复旧 footprint：**逐格**比对"当前格 == 该格模板期望方块（jigsaw 用 `final_state`）"，不等就**跳过**；
   恢复材质 = 该列**下方第一个"像地形"的方块**（非空气/非流体/无方块实体/非 `bettergold:*`/非 jigsaw），
   找不到就往上找，再找不到用 `minecraft:netherrack` 兜底（实测 55 格全是 `minecraft:basalt`，见 15.5）；
   ③ **口位格 M 保持空气**（门道）；④ 实体去重（同一格只留一个）。
6. **记账**：一条 `[bgp-exit] …` 日志 + 诊断环（`chunk / outcome / dist / strict / cand / overwroteNatural /
   restored / skipped / doorway / writes / violations / materials`）。

### 16.10 修法：逐格模型（与上一轮"整箱 bbox 当墙"的差别）

| # | 上一轮/上一会话 | 本轮 | 依据 |
|---|---|---|---|
| 1 | 洪泛只挡"旧 footprint 全部格"（含 44 个模板空气格） | 只挡**放置后是实心**的格（`placedBlockId != air`）；模板空气格 + 口位格 M 可走 | A 级：旧口径 `reachable=28`（只有父件内部那点空气），33 个出入口 **0 候选** |
| 2 | 其它件的 **bbox 整箱**当墙（含父件） | 其它件按**自己的模板逐格**展开：实心格当墙、air 格当"最终世界一定是空气"（件还没放时地形可能还是岩体） | A 级：bbox 口径把件内走廊也当墙 ⇒ `reachable=28`、`cand=0`；逐格口径 `reachable=383..4719` |
| 3 | 目的地"不相交或相邻（≥1 格）" | **保留**（`candBox.inflatedBy(1)`）；搬迁件的新 bbox 与所有别的件 bbox 至少隔 1 格 | 后放的件不会贴脸；本轮 0 搬迁，这条只在候选筛选用到 |
| 4 | 没有"最终世界复验" | 洪泛 = **最终世界的空气图**：模板实心格（含未放置的件）+ 当前地形（窗口内已 FEATURES） | 读源码：件是"先算 bbox、再逐区块 postProcess"；模板 `blocks` 里 air 格会被写成空气，`structure_void` 不进模板（地形原样） |

**为什么"整箱 bbox 当墙"不行（这是上一会话没有走完的一步）**：
bbox 里既有墙，也有**件内的走廊/门道/3×3×3 房间**（模板 air）。整箱挡掉 = 把所有件之间的通道
也焊死；A 级实测（A 世界那次 bbox 口径）：旧口位洪泛只剩**父件内部那 28 格**，33 个出入口 **候选 = 0**，

洪泛才真的是"从 M 沿牢狱走廊走出去、到空域、再回到 M'"这一条。

**为什么"未放置件的 air 格"必须算可走**：`afterPlace` 时别的件可能只放了当前区块那一片；
它的**实心格**现在还是地形（岩体），但最终一定会变成墙 ⇒ 障碍；它的 **air 格**现在也还是地形
（岩体），但最终一定会被写成空气 ⇒ **必须可走**，否则洪泛连牢狱走廊都走不出去
（实测：只挡实心、不补 air 时，`reachable` 只有 45~3526，远小于最终世界的连通域）。

**为什么没有用第 3 步"可走带 ±2"**：可走带只会**缩小**洪泛范围，不能把"不可达"变成"可达"；
逐格模型已经在**最终世界**里判连通，剩下的不可达是"局部窗口里真的没有空域"，不是"走进了

### 16.12 搬迁数 = 0：为什么一个都不搬（**如实报**）

| 读数 | A | B |
|---|---|---|
| 生产洪泛（`afterPlace` 里，窗口 = 当前区块 ±1，48×48） `reachable` 范围 | 383–4719 格 | 同量级 |

- **几何原因（读 exit.nbt 逐格）**：exit = 5×8×5 / 174 条 blocks = **129 实心 + 1 jigsaw + 44 air**；
  44 air = **3×3×3 房间 27** + **3×3 口位面 9** + **顶部通风角 8**。**jigsaw 在 z=0 那一面，
  其余五面是实心壳 ⇒ 这个件只有一个开口，朝父件**。搬走以后，旧位置只剩"朝父件的 3×3 房间"
  （一个死胡同）——**玩家不可能从旧房间走到新位置**；新位置是否可达，只取决于
  "牢狱里其它开口 → 空域 → 新口位面"这一条。
- **窗口原因**：`afterPlace` 只能读/写**当前区块 ±1**（48×48）。本轮的 61 个口，
  局部窗口里的可达空气只有 383–4719 格，且**没有一格 5×8×5 的空腔**（`cand=0`）；

  大空域在**窗口之外**，`afterPlace` 看不见。
- **上一轮的 10 个搬迁件为什么是假通**：旧口径只用 `level.isAir()`；**件还没放的实心格**
  如果恰好是洞穴空气，就会被当成可走——于是"从父件穿墙出去 → 洞 → 目的地"在生成期成立，
  件一放就断。本轮把"未放置件的实心格"按模板当墙后，那些目标位置全部落到 `cand=0`。
