## 0. 结论先行（8 条）

1. **20 个模板** = 作者原有 14 件（P01~P14）**全部保留** + 6 个新变体（3 个尺寸 × 镜像/丰饶各 1）。
   原 14 件的方块数**逐件与上一轮取证完全一致**（2195 / 6280 / 6277 / 1755 / 1752 / 1742 / 1212 / 1200 / 1184 / 670 / 663 / 644 / 48 / 155）。
2. **口位不是手写的**：脚本在每件的 4 个边界面上扫「3 宽 × 3 高 + 向内一格也为空」的洞，扫出来的 14 件口位与 `拼接分析.md` §3.5/§4.1 的**表逐条一致**（宝藏房南 `(10,3,20)`、四面道四口 `(18,1,0)/(18,1,36)/(0,1,18)/(36,1,18)`、牢房 `(7,1,0)/(7,1,sz−1)`、过道 `(2,1,0)/(2,1,2)`、出入口北 `(2,1,0)`）。
3. **jigsaw 42 个**（20 件：1+4+4+2+1+2×12 … 逐件见 §2 表），`final_state=minecraft:air`、`joint=aligned`，
   **orientation = 该口实际的外侧方向**（关卡按坐标复算，不信任表）。
4. **方向闸**：181 组（父口 × 子件 × 4 个旋转）全部通过；断言 ① 两口同面同高 ② 洞底 = 行走面（拼完行走面连续）③ orientation = 实际外侧 ④ 两件包围盒不重叠。**错一格/反一个朝向必红**（§5 扰动矩阵 P1/P2）。
5. **唯一性靠构造**：`start_pool = 宝藏房 ×1` ⇒ 每次生成只 roll 一次起点 ⇒ 宝藏房天然唯一。A 级实测**宝藏房恰好 1 个 / 出入口 3 个 / 18 件 / 9 个不同模板**。
6. **「四面道四口都连」与「宝藏房唯一」同时成立**（作者 ③）：四面道 4 个口全留 jigsaw，分叉由 `size=6` + 碰撞检查自然收敛；宝藏房因为**只能是起点**而唯一。
7. **小牢房三步循环**（作者 ②）：`过道南口 → cell_small_1(A) → cell_small_2(镜像) → cell_small_3(丰饶) → 回过道`。三条都是**双口同名同目标**的同构写法 ⇒ 引擎随便选哪个旋转都成立；一次连出来的小牢房**必然是 3 件、必然含丰饶版**。
8. **战利品**：单池 27 条（xlsx 28 行**减 1 行算不出来的**，见 §4.2），权重和 80、`rolls` 均匀 5..10、**无 empty 条目**（作者：没有空箱率）、`bonus_rolls = 1.0`。
   **幸运走 `LootPool#addRandomItems` 的 `rolls + floor(bonus_rolls × luck)`**（源码 `LootPool.java:108` + `RandomizableContainer#unpackLootTable` 的 `withLuck(player.getLuck())`），A 级实测 **luck0 均值 29.13 → luck3 均值 39.98 件**。

## 1. 六步逐段

### 第 1 步：抠 14 件 + 造 9 种造型（①的落地）

**做了什么**（`docs\金之牢狱-实现-证据\gp_build.py --stage 1`）：

- 复用上一轮的自写 NBT/.mca 解析器（`nbt.py` 原样复制，SHA256 `CE5FFE98…`），把存档里 14 个件的方块**逐格读进内存**（键 = 相对坐标，值 = `[方块 id, 属性字典]`）。
- **变体 B = 南北轴镜像**（`x → sx−1−x`）：属性按面翻（`facing` 东西互换、`east/west` 两个布尔互换（含"只有一边为 true"的墙/栅栏/玻璃板）、楼梯 `shape` 的 `inner/outer_left ↔ right`，`axis`/`age`/`moisture`/`half` 不动）。
- **变体 C = 丰饶版**：在 A 件**内部**挑一块「全部可站、且不与过道口列冲突」的最大矩形（small 2×3 / medium 3×3 / large 3×3），
  把地面换成 `gold_infused_farmland`、上面种 `golden_wheat_crop` / `golden_carrot_crop` / `golden_eggplant_crop`、
  放 2 个 `golden_toad_figurine`、**最远那一格放箱子**（不挡道）。**所有方块与属性都从 P02 中央农田 / P03 金蟾与箱子原样搬**（含 crop 的 `age`、farmland 的 `moisture`、chest 的 `facing/type`），**没有自己造任何新造型**。
- 自检：镜像件「镜像两次 == 原件」；镜像后块数/调色板/口位三重相等；丰饶版**只动了 `1 ≤ x ≤ sx−2`、`1 ≤ z ≤ sz−2`、`y ∈ {walk_y−1, walk_y}`**（外壳、屋顶、过道口列**一格未动**），且必然有箱子、必然有作物、调色板不越界（只允许新增 farmland/三种作物/金蟾/箱子）。

### 第 2 步：注 Jigsaw（20 件 / 42 个口）

**做了什么**（`--stage 2`）：每个口在**洞口那一格**（边界层、口底正中）放 `minecraft:jigsaw`——
`orientation = <外侧>_up`、`name/target/pool` 按下面的接线表；块实体另带 `final_state=minecraft:air`、`joint=aligned`、
`placement_priority=0`、`selection_priority=0`。⚠ **不是"内侧一格"**：引擎的对齐公式是
`B.origin = A.origin + 父口 + D − 子口`，jigsaw 必须落在**件自己的边界格**上，子件才会"面贴面"；放进内侧一格会让子件**插进父件内部**并被碰撞检查拒绝（关卡 `[bgp-gate]` 的 ①② 就是照这个写的）。

**接线表（15 个池的语义）**

| 模板 | 口 | `name` | `target` | 引用池 |
|---|---|---|---|---|
| treasure | 南 | `room` | `lane` | `lane` |
| cross_a / cross_b | 四口 | `room` | `lane` | `lane` |
| cell_medium_* / cell_large_* / cell_small_b / cell_small_c | 南北 | `room` | `lane` | `lane` |
| **cell_small_a** | 南北 | `cell_small_1` | `cell_small_2` | `cell_small_2` |
| **cell_small_mirror** | 南北 | `cell_small_2` | `cell_small_3` | `cell_small_3` |
| **cell_small_fertile** | 南北 | `cell_small_3` | `lane` | `lane` |
| lane（过道） | 北 | `lane` | `room` | `room` |
| lane（过道） | 南 | `lane` | `cell_small_1` | `cell_small_1` |
| exit（出入口） | 北 | `lane` | `room` | `room` |

**为什么小牢房是三步循环**：三个小牢房变体的**两个口同名同目标**（同构），所以引擎无论挑哪个旋转、
父件从哪一头接进来，**剩下来的那个口**都指向下一步 ⇒ `A → 镜像 → 丰饶 → 回房间`，一次连出来的小牢房恰好 3 件且必含丰饶版。
`cell_small_1/2/3` 三个池的 `fallback` 都指向**自己**，所以即使 `size` 在链子中间截断，下一步也照样会补齐（不会留下一截断头）。

**读数**：20 件共 **42 个 jigsaw**（宝藏 1 / 四面道各 4 / 12 个牢房各 2 / 过道 2 / 出入口 1）；每件的口集合与 §3.5 表一致；每件 jigsaw 数量 == 口数（自检直接读 NBT 数）。

**遗留**：`lane` 的两个口**故意不对称**（北回房间、南进小牢房链）——这是"三步循环"唯一可行的接线方式（`canAttach` 只认"父 target == 子 name"的单向匹配）。代价：引擎在两个等价旋转里随机挑一个，所以约一半的过道通向小牢房链、一半通向普通房间。**这一点已记账，作者觉得"过道一半都通小牢房"太多的话，最小改法是给 `lane` 池加第二个变体（两条口都通房间的过道）并按权重配比。**

### 第 3 步：导出 `.nbt` + 俯视蓝图

**做了什么**（`--stage 3`）：自写 NBT writer（`DataVersion=3955`、`size` / `palette` / `blocks` / `entities` 四个根键，1.21 路径 **`data/bettergold/structure/`**，不是 `structures/`）；
箱子的块实体写 `LootTable = bettergold:chests/golden_prison`（**逐箱写**：20 个模板里一共 **23 个箱子**，来源 = 作者原件的 14 个 + 3 个镜像件各 1 个 + 3 个丰饶件各 2 个）。
gzip 用 `mtime=0` ⇒ **字节可复现**（连跑两次 SHA 相同，已实测）。

**逐格自检**：每个 `.nbt` 写完后**重新解析**，把方块集（坐标 → id + 属性）与第 2 步的内存件**逐格比对**，不一致就 `SystemExit`。20/20 通过。

**蓝图**：`docs\金之牢狱-蓝图\` 20 张 PNG + `README.md` 索引。每张是**可行走面那一层（walk_y）的平面图**：
绿 = 能站的空气、金 = 作者原有金方块、洋红 `J` = jigsaw 口位、`C` = 箱子、`S` = 刷怪笼，带 **N/S/E/W** 与每 5 格一条坐标刻度（原点 = 结构框西北角）。

**读数**：20 个 `.nbt` 共 **33,117 个方块条目**（含 42 个 jigsaw），文件 484 B ~ 20.8 KB。逐件尺寸/方块数/SHA256 见 §8 与 `nbt_manifest.json`。

**遗留**：蓝图的"可站"判据是**几何**（该格 air + 下面一格实心），不判"玩家真的走得到"；真正的连通性由第 6 步 A 级的**逐格 junction 检查**兜。

|---|---|---|

| `lane` | lane(1) | **`exit`** ← "到临界点换成出入口" |

**口径记账（我拍的）**：
- **`size = 6`**：沿一条路 = 宝藏(0) → 过道(1) → 房间(2) → 过道(3) → 房间(4) → 过道(5) → 房间(6) → **出入口(7)** ⇒ 一条路 **3 段房间 + 3 段过道**（满足"至少 2–3 段房间"）。`size` 是**偶数是刻意的**：偶数值让最深那件是"房间"，它的口 target=lane ⇒ 走到 `lane` 池的 fallback ⇒ **每条分支末端正好一个出入口**。
- **`spacing=32` / `separation=16`**（chunk）：结构最大跨约 143 格（A 级实测 bbox 143×34×128），32 chunk = 512 格，够散开。
  > ⚠ **第三轮（2026-10-20）就地标注**：已按作者要求改成 **27 / 4**（= 下界要塞），见 §10.3；原值保留。
- **`max_distance_from_center=100`**：`terrain_adaptation != none` 时 `max_distance_from_center + 12 ≤ 128`（`JigsawStructure.verifyRange`），100+12=112 ✓。
- **出入口的 `target`**：作者原话只到"出入口是终点"。**我给它 `target=room` + 引用 `room` 池**——因为它的口是"被父件接上"的那一头，`target` 只在"它自己被展开"时才用到；给它 `room` 可以避免 `minecraft:empty` 池的 `Empty or non-existent pool` 警告，同时**不会**真的继续长（它只在 `depth == maxDepth` 时被放，`depth+1 > maxDepth` ⇒ 不再展开）。侧证：A 级里 34 个口**全部成对**、0 个"落单"，出口没有多长东西。
- **中/大牢房不做三步循环**：它们的三个造型**权重随机**（`room` 池里按权重 roll），因为作者只对"三件连一起的小牢房"提出固定要求。

**遗留**：`cell_medium_*` / `cell_large_*` / `cross_a` / `cross_b` 这四个（组）池**没有被任何 socket 引用**——它们的件已经通过 `room` 池参与生成。保留它们是为了让"一个变体一个池"的目录结构完整、方便作者以后单独调某一个变体的权重；如果作者觉得多余，删掉 6 个文件不影响生成。

## 9. 阶段 B 追加：P0「模板完全没有空气」的修复与复验（2026-10-20 第二轮）

> **一句话**：上一轮 20 个 `.nbt` **一条 `minecraft:air` 都没有**（`gp_build.py` 抽件时 `if nm in AIR: continue`），
> 于是放置时**地形没被挖开** —— 房间/走廊被下界岩灌满、门洞只有 1 格。
> 本轮只改 `.nbt`（**只多出空气条目**）+ 关卡 + 文档，**不改 Java / 不改池与结构 JSON**。

### 9.1 根因与修法（逐行可复算）

| 环节 | 修前 | 修后 |
|---|---|---|
| `gp_build.py` 抽件 | `if nm in AIR: continue` ⇒ 空气在第 1 步就被丢掉 | 不再跳过（空气留在件里） |
| `gp_build.py build_nbt()` | 只遍历 `piece['blocks']` ⇒ palette 里没有 `minecraft:air` | **逐格写满件自己的 bbox**：没有显式方块的格子写 `minecraft:air`；只写件内，不带件外世界空气 |
| 导出后自检 | 只比"方块集 == stage2" | 再加两条：`条目数 == 满体积`、`空气数 == 体积 − 非空气`；`nbt_manifest.json` 每件多记 `volume`/`air` |
| 关卡 | `[bgp-gate]` 只验口位那一层 | 新增 `[bgp-air]`（逐件空气 / **逐口两层 3×3×1** / 行走层 / 件内洪泛）+ `[bgp-connect]`（虚拟拼一座，从宝藏房洪泛到每个出入口） |

**为什么模板空气是关键**：`StructureTemplate#placeInWorld` 把模板里**写了的每一格**（含 `air`）都放下去，
**模板空气负责把地形挖成房间**；模板里没有的格子 ⇒ 地形原样保留。修前只有 jigsaw 的 `final_state=air` 挖了 1 格。

### 9.2 读数（静态 + 两个种子的 A 级）

**静态（20 件，不跑游戏）**

- 条目数 **== 满体积：20/20**（`cell_large` 2790 = 15×6×31、`cell_medium` 1890 = 15×6×21、`cell_small` 990）；
- `palette` 含 `minecraft:air`：**20/20**；空气条目合计 **21381 / 54498 = 39.23%**；
