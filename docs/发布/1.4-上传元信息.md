## Beta / Release 建议

**建议标为 Release（正式版）。**

理由：

1. 构建通过，产物 jar 与当前源码一致，且不含任何调试或诊断代码。
2. 三套金属的注册与数值（每套 24 件物品 / 11 个方块、器具伤害与攻速 10/1.8、12/1.2、8/1.4、8.5/1.2、7/4.2、7.5/2.2、盔甲 5/10/8/5 与耐久 814/1184/1110/962）、万坚金迁移"零行为变化"、创造页 1 页 5 分区 206 件、三种状态效果、建材接触效果、金属小刀特性、落雷与音效，都有实机运行记录佐证。
3. 数据侧自检全绿：三套金属的 207 个资产 JSON 全部可解析、引用的贴图无缺失；93 个语言键中英双语零缺失；33 张方块战利品表齐全；235 个配方文件全部可解析。

保留意见：**烈燃金自动熔炼**与**盔甲抗性/反制的几率**这两项只有代码实现、我未能找到实机验证记录（见下一节）。如果你希望"发布即全部实机验证过"，可以先自己跑一次这两项再上传；不介意的话直接 Release 也合理。

## 未包含 / 未验证（作者自阅）

> 这一节只给你自己看，**不要**贴进公开变更日志。

1. **烈燃金自动熔炼（未验证）**：`MetalEvents.onBlockDrops` 已实现（先查熔炉、再查高炉配方表，含下界金矿的特殊输入处理），但我没有找到"实机挖原木/沙子看掉落"的验证记录。
2. **盔甲抗性与反制几率（未验证）**：`MetalEvents.onDamagePre / onDamagePost / onLivingTick` 已实现（每件 25% 减伤、每件 25% 反制几率、穿满四件 100% 免疫与反制，完整套数还会清中毒/虚弱/颤栗），但我没有找到运行时验证记录。
3. **落雷音效的三个档位**：只有默认档 `client_payload` 实测过（客户端确实播到了 impact 与 thunder 两条原版音效）；`vanilla_local` 与 `server_broadcast` 两个备选档未验证。
4. **高燃每秒伤害的口径与规格文档不一致**：规格写的是「0 级 1 点、1 级 2 点」，代码与实测是 `amplifier + 2`，即 **1 级 2 点/秒、2 级 3 点/秒**。对外文案按代码/实测写的，规格文档那句话可以顺手改掉。
5. **巫毒羽毛掉落率**：`MetalSpecialItems` 的注释写「女巫 6% 掉落」，实际掉落表是 **基础 36%**（每级抢夺 +6%）。对外文案按掉落表的 36% 写。若你的本意是 6%，需要改 `data/bettergold/loot_table/inject/witch_voodoo_feather.json`。
6. **烈燃金建材的着火频率（已知行为，非缺陷）**：因为每次接触都会把着火时长刷回 120 tick，实际燃烧约 2 点/秒（原版燃烧是 1 点/秒）。这一条本次刻意没有动，如果你觉得太强可以再议。
7. **旧存档升级（未验证）**：1.4 没有删除任何物品 / 方块 id（只删了一个空类文件），理论上 1.3 存档可直接加载，但我没有实际用 1.3 存档升到 1.4 跑过。
8. **客户端 / 服务端版本一致性（未验证）**：1.4 新增了自定义网络通道，只测过"同版本客户端 + 服务端"。混装（1.4 客户端连 1.3 服务端）没有验证过，建议在页面上注明"客户端与服务端需同版本"。
9. **`META-INF/neoforge.mods.toml` 的显示名与描述仍是旧文本**：`displayName` 还是 `bettergold`，`description` 还是 1.3 时期那段（只提万坚金）。本次没有改动仓库已有文件，你可以自行决定要不要更新（更新后需要重新构建 jar）。
10. **未发现"设计了但没做"的内容**：1.4 规格里列的三套金属（材料链 / 建材 / 器具 / 盔甲 / 模板）、三种效果、建材接触、盔甲抗性反制、纹饰色卡、自动熔炼、落雷，逐条在代码里都能对上。
11. **小刀修好后的副作用（待你裁决）**：金属小刀现在被认定为合法器具，而挖掘自动熔炼只判定"是不是这个金属的器具"、不区分具体种类，所以**烈燃金小刀也会自动熔炼方块掉落**。如果这不是你要的，只需要在 `MetalEvents.onBlockDrops` 的判定里再加一句"并且不是小刀"（对外文案里没有单独提这件事，写的是"烈燃金器具"）。
