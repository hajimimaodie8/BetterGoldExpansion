### 30.3 A3 · 巫毒爆发必须是魔法伤害（真正的原因不是「类型错了」）

- **查证（读源码 + client-extra jar）**：1.21.1 的 `minecraft:magic` **本来就在
  `data/minecraft/tags/damage_type/bypasses_armor.json` 里** ⇒ 它**不吃护甲点**。
  「旧结论说本来就是 magic」这一点类型上没错；作者仍觉得「物理」的真正来源是**保护附魔**：
  `LivingEntity#getDamageAfterMagicAbsorb` 对**所有**非 `bypasses_enchantments` 的伤害都算保护附魔，
  满保护 IV 把 10 点魔法伤害从 6.0 压到 **2.16**（64%）。
- **改法（不依赖原版标签的既有内容）**：
  - 新增自带 damage type `bettergold:voodoo_burst`
    （`data/bettergold/damage_type/voodoo_burst.json`：`message_id = "magic"` 复用原版死亡提示、
    `exhaustion = 0.0`、`scaling = "when_caused_by_living_non_player"` 与 magic 同档）；
  - 新增 `data/minecraft/tags/damage_type/bypasses_armor.json`（`replace:false` + `bettergold:voodoo_burst`）
    **显式**登记「不吃护甲点」；
  - `metal/MetalEvents.java` 的 `voodooSettleSource` 改用
    `ModDamageTypes.source(serverLevel, ModDamageTypes.VOODOO_BURST, null, owner)`（owner 保留，
    找不到施加者时也仍是同一个类型）；`isMagic` 增加 `VOODOO_BURST`（否则巫毒金盔甲的「每件 25% 魔法减免」会静默失效）。
- **A 级（真 `ServerPlayer`，`probe/bgbig/VoodooProbe`，12 PASS / 0 FAIL）**：

| 用例 | 读数 |
|---|---|
| 裸玩家，10 点 | 掉血 **6.0** |
| 穿满钻石甲（armor=20 / 韧性 8，无附魔） | **6.0**（比值 **1.0000**，护甲点不减免） |
| 穿甲 + 抗性提升 I | **4.8**（比值 **0.8000**，魔法抗性生效） |
| 穿甲 + 保护 IV | **2.16**（原版 magic 同样吃保护附魔，如实记录） |
| 穿满巫毒金 4 件 | **0.0**（4 × 25% 魔法减免仍认新类型） |
| 真结算：裸僵尸 / 穿钻甲僵尸 | **4.6 / 4.6**（10×0.36+1，type = `bettergold:voodoo_burst`） |

  实际 `DamageType` registry id = **`bettergold:voodoo_burst`**，`BYPASSES_ARMOR = true`，owner = 施加者 UUID。
- **裁定（父代理 2026-10-24）**：**不加 `bypasses_enchantments`**：加了会变成「比原版魔法更强」，
  作者没要。若日后要连保护附魔也不吃，只需再加一句话（并把本文这一行改成新口径）。
