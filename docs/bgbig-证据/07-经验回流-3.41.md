### §3.41 四个「看着像 A 级、其实是驱动层 / 结构层」的探针坑（`bgbig` 轮，2026-10-24，bettergold）

**① 探针 `ServerPlayer` 的 `inventory_changed` 不会自己触发**
`ServerPlayer` 的容器监听只在 `initInventoryMenu()` 里挂（不是构造器），且它内部
`setSynchronizer → sendAllDataToRemote` 会走 `connection` ⇒ **必须在 `connection` 装好之后**再调；
探针玩家不 tick ⇒ 加完物品还要 `player.inventoryMenu.broadcastChanges()`。
**规则**：探针要验「获得即解锁」类成就时，按 `initInventoryMenu()` → `Inventory#add` →
`broadcastChanges()` 三步走；`FakePlayer`/未初始化菜单的实例读数会全是 false（假阴性）。

**② Patchouli 的配方页「每页 2 个」还隐含「同一种 recipe class」**
`PageDoubleRecipe` 的子类各自只认一种配方类型（`PageCrafting` → CraftingRecipe、
`PageSmelting` → SmeltingRecipe）⇒ 「上 = 熔炉、下 = 工作台」**不能同页**，`recipe2` 会被过滤成空槽。
**规则**：跨机器/跨类型的两个配方 = **拆成相邻两页**（不是硬塞 `recipe2`）；页数变化要记账。

**③ `requirements` 的组语义：组内 OR、组间 AND**
派单若写「两个都要 ⇒ 组内 AND」是把语义写反了。要「两个都要」必须写成**两个各一条判据的组**
（`[[a],[b]]`）；写成 `[[a,b]]` 是「任一即可」。**依据**：`AdvancementRequirements#test`（源码级）。

**④ 作者给的新 `zh_cn.json` 要以 `git show HEAD` 为基线比对**
本轮 B/C 已经往当前语言文件加过新键，直接拿"当前文件"比会把本轮新键误判成"作者漏了"。
正确做法：`git show HEAD:<lang文件>` 取基线 → 作者文件缺的键**必须恰好等于本轮删掉的旧条目**
（本轮 26 = 22 手册 + 4 被毙成就），多一个/少一个都停下报告。

**⑤ 顺手一条（伤害类型）**：改「魔法伤害」前先读原版标签 —— 1.21.1 的 `minecraft:magic`
**本来就在 `#minecraft:bypasses_armor`**；作者若仍觉得"物理"，先查**保护附魔**
（`getDamageAfterMagicAbsorb` 对所有非 `bypasses_enchantments` 的伤害生效），不要先怀疑类型 id。

**依据等级**：①②③ `【实测】` 本轮真 `ServerPlayer` / 真 `BookContents`；④ `【实测】` HEAD vs 作者文件 diff；
⑤ `【读源码】` client-extra jar 的 `bypasses_armor.json` + `LivingEntity#getDamageAfterMagicAbsorb`。
