## 二、已落地的两处修正（批 3）

### 2.1 §5.2 创造页横幅的 Z 深度 bug

**现象**（作者原话）：鼠标移到横幅**下方**的物品时，那个字（tooltip / 名字）被横幅盖住。

**根因（源码级，两条叠加）**

1. **不是"z 不够"，是"画得太晚"**：`AbstractContainerScreen#render` 第 141 行
   `RenderSystem.disableDepthTest()` 把**深度测试整个关掉** ⇒ z 参数不参与遮挡判定，
   只有**绘制顺序**说话。所以「改 z 深度」这条方向**物理上无效**（需求的验收也不许靠隐藏/降透明度绕过）。
2. 旧落点 `ScreenEvent.Render.Post` 由 `ClientHooks.java:429-430` 在
   `screen.renderWithTooltip(...)`（tooltip 是**最后**一步，`Screen.java:111-117`）**整段之后**才发
   ⇒ 横幅必然压在 tooltip 之上。参考实现（航空学）注入的是 `render` 的 TAIL（= tooltip 之前），
   所以它没有这个 bug —— **旧注释里那句"两者时序等价"是错的**。

**改动**

| 文件 | 改什么 |
|---|---|
| `client/CreativeSectionBanners.java` | 事件入口 `ScreenEvent.Render.Post` → **`ContainerScreenEvent.Render.Foreground`**（`renderLabels` 之后、tooltip 之前；其 javadoc 原文就是 "after … foreground layer … **before rendering the tooltips**"）；方法名 `onScreenRender` → `onContainerScreenForeground`；取界面改用 `event.getContainerScreen()` |
| 同上 | **坐标改容器相对**：该事件在 `pose().translate(leftPos, topPos, 0)` **之内**发出（`AbstractContainerScreen:142-143`，push 后未 pop）⇒ `int left = ITEM_AREA_X;` / `int top = ITEM_AREA_Y;`（不再加 `guiLeft/guiTop`） |
| 同上 | 删掉已无调用点的 `guiLeft(...)` / `guiTop(...)` / `readInt(...)` 三个反射助手（**整块删除、不是注释掉**，旧口径写进类 javadoc 留档） |

**验收（B 级已完成 / A 级待办）**：静态关卡 `[bg16-banner-foreground]` / `[bg16-banner-relative-coords]` /
`[bg16-banner-old-event]` / `[bg16-banner-no-absolute-coords]` 全绿 + 扰动实测逐条命中（`docs/bg16-证据/01`）。
**A 级待办**：`runClient` 里逐个悬停横幅下方的物品，确认名字与 tooltip 都在最上层、横幅仍清晰可见。

### 2.2 §5.1 安抚 buff 对玩家生效

**口径**（作者原话）：「安抚 Buff 对玩家起效为**禁止移动** + **无法使用左右键**」。

**实现（全部运行时判定，`player.hasEffect(AllEffects.SOOTHE)` 是唯一判据）**

| 落点 | 做法 |
|---|---|
| 禁止移动 / 禁止跳跃 | `PlayerTickEvent.Post`（仅服务端）：安抚在身 ⇒ 给 `MOVEMENT_SPEED` 与 `JUMP_STRENGTH` 各挂一个 **`ADD_MULTIPLIED_TOTAL` −1.0**（= ×0）的 **transient** 修饰符；不在身 ⇒ `removeModifier`。两条属性都是 `setSyncable(true)`（`Attributes.java:80-81,114-116`）⇒ **客户端读到的就是 0**，按键不产生输入、无需网络包，也不会有"橡皮筋" |
| 左右键全部用途 | 7 个处理器：`AttackEntityEvent`（攻击）/ `BlockEvent.BreakEvent`（破坏）/ `PlayerInteractEvent.{LeftClickBlock, RightClickBlock, RightClickItem, EntityInteract, EntityInteractSpecific}`，一律 `setCanceled(true)`（`LeftClickBlock` 没有 `setCancellationResult`，只 cancel） |

**★ 可逆性（本轮第一优先级）**：**零持久状态** ——
不写 NBT、不进 `SootheState`（非 `Mob` 本来就直接 return，玩家的 `restore/clear` 天然是空操作）、
修饰符是 transient（不落盘），而且每 tick **双向**判定。
⇒ 自然到期 / 牛奶 / 指令 / 死亡 / 退服 / 重启，任何一条路径下一 tick 都恢复原状，
**结构上不可能出现"被安抚过的玩家永久不能动"**（这正是 `SootheState` 那段血泪注释的教训）。
关卡用 `[bg16-soothe-state-untouched]` 把"既有生物机制一个字没动"钉成**恰好三处守卫**的反向不变量。

**验收（B 级已完成 / A 级待办）**：静态关卡 + 扰动 12 例（`docs/bg16-证据/01`）。
**A 级待办**：真人玩家上施加安抚 → 试走动/跳跃/左右键各自无效 → 到期后确认能动能用键，
**反复 10 次**（需求 §6.3 明写）。

## 三、动手前已定好的口径（批 1 / 批 2 / §3.8，实现时照此）

1. **两族 Spec 一个数值字段都不覆盖**：`MetalFamily.Spec` 默认值（4096 / 24 / 14F / 4.5F /
   护甲 5·8·10·5 / 耐久 962·1110·1184·814 / 韧性 6F / 击退 0.15F）与 1.6 规格**逐项相同**，
   逐件伤害/攻速也由 `1 + 4.5 + 每武器常量` 自动得出（剑 10/1.8、斧 12/1.2、镐 8/1.4、锹 8.5/1.2、锄 7/4.2、刀 7.5/2.2）
   —— 这组反算是【读源码 + 算术】，**必须实机复核**。
2. **重锤 ×1.2 与三叉戟投掷 15 不用新写**：`MetalEvents.onMaceFinalDamage`（按 `MaceItem` 判）与
   `onTridentThrownDamage`（按族 `isWeapon` 判）已是**全局**规则，新金属自动继承。
3. **免疫仙人掌（两处落点，都不需要 Mixin；源码取证见 `docs/bg16-证据/05`）**：
   - 物品形式 → `EntityInvulnerabilityCheckEvent`（`ItemEntity#hurt` 第一句就问 `isInvulnerableTo`）；
   - 装备耐久 → `ArmorHurtEvent`（原版循环已被 NeoForge 废掉，盔甲耐久唯一执行点）。
4. **两个 buff 的数值**：寄生 = 等级 1/2/3 ⇒ 每秒 1/2/3 点 `cactus` 伤害、时长 **320 tick（16 秒）**、
   叠加无上限、每次伤害结算时 36% 概率给施加者回 `等级` 点血（施加者 UUID 记在目标持久数据）；
   幽咆 = 每秒以目标方块坐标 ±1（3×3×3，含自己）造成 `等级` 点 `sonic_boom` 伤害 +
   `SONIC_BOOM` 粒子，时长 **120 tick（6 秒）**，叠加提升等级。
5. **盔甲 25% / 全套 100%**：减免 `damage × (1 − 0.25 × 件数)`、反制 `min(1, 0.25 × 件数)`，
   与既有靛海金 `counterChance` 同构（照抄，不另造口径）。
6. **建材 trait**：树棘金 = 四动作 ⇒ 对触发者 1.0 点 `cactus`；幽咆金 = 四动作 ⇒
   方块中心 3×3×3 全部生物 3.0 点 `sonic_boom` + 粒子；冷却复用既有 10 tick 语义、
   **每族独立键**；**不清除掉落物**（= 新代码里不许出现任何 `ItemEntity` 摧毁逻辑，写成负向断言）。

   判据 = 方块 ∈ `#minecraft:leaves` ∪ `minecraft:vine` 且工具 ∈ 本模组全部族器具/五类武器；
   概率 `p = 0.06 + 0.06 × 时运等级`；另加 `Compostable(0.65f)`。

   否则**静默不生效**（关卡要断言这一条）。

## 7.3 本轮的三条探针工程教训（都写进 `mcmod_experience.md`）

3. **接触类 3×3×3 的盒子以方块坐标为中心**（y 99..101）：**站在方块顶上**（脚 y=101.0）的实体落在盒子边界上被排除；且「触发者挨打」与「方块周围挨打」是两条作用域，受试体必须站在旁边的地面上。
