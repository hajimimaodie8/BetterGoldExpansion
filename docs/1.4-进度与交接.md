## 〇、本轮（1.4 补丁）改了什么

- **巫毒改成「累积伤害 / 秋后问斩」模型**（替换旧的 等级 × 0.6% × 最大生命）：
  窗口内目标受到的每一次伤害按 `voodooStoreRatio`（默认 0.8）累积，效果**自然到期**时结算
  `存储 × (1 + voodooReleasePerLevel × 等级)`（默认 0.8/级）。累积放在服务端
  `material/VoodooAccumulator`（`Map<UUID, Double>`，baked 在 Expired/Remove/Death/LeaveLevel/LevelUnload 上清理，
  另有 600 tick 兜底扫描）；结算自身伤害用 settling 标记排除，不喂回累积。
  两个系数在 `config/bettergold-common.toml`：`voodooStoreRatio` / `voodooReleasePerLevel`。
- **结雷金落雷音效改为三档** `thunderSoundMode`：`client_payload`（新默认，服务端发
  `bettergold:thunder_sound` payload，客户端用原版同一条 `playLocalSound` 播放，**不依赖客户端雷实体**）、
  `vanilla_local`（原版机制）、`server_broadcast`（服务端广播）。客户端还会把「同一坐标、紧随 payload
  之后播出的那一份原版雷声」静音 10 tick，避免一次落雷响两遍。
- **启动自证**：日志固定打一行 `BETTERGOLD-STARTUP modVersion=… thunderSoundMode=… thunderSoundModeKeyPresent=…`
  （`config/StartupSelfCheck`），用来判断作者手里是不是旧构建。
- **修复：三把金属小刀攻击不触发金属特性**（作者反馈：烈燃金刀 / 巫毒金刀 / 结雷金刀攻击时对应特性全都不生效）。

    （`MetalFamily.java:259`）；而乐事联动那几把刀是 FD 模块用反射工厂创建、经
    `fd/FdItems.registerMetalKnives()` 的 `addExtraItem(...)`（`FdItems.java:207` / `:214`）登记的，
    它们只进了 `tools()` 的 `extraItems`，**没进 `BY_ITEM`**；唯一会写 `BY_ITEM` 的 `mapExtraItem`
    是**零调用死代码**。于是 `MetalEvents.onLivingDamaged` 里 `MetalFamily.of(刀) == null`，
    在 `MetalEvents.java:362` 直接 return，什么都不派发（万坚金刀同样中招；古董刀 / 下界合金古董刀
    本就不属于家族，返回 null 是正确的）。
  - **修法（唯一真相处，只改 `material/MetalFamily.java`，+43/−8）**：建索引时把本体物品与额外部件
    **一起**写进 `BY_ITEM`（新增 `resolve(Supplier)` 兜住注册期未绑定，解析不到就跳过，

    删掉死代码 `mapExtraItem` 与其上重复错位的 javadoc。`MetalEvents` / `FdItems` / tier 判定 / `ModEvents`

## 三、这套流程里踩过的坑（别再踩）

- **注册期不能 `.get()`**：`DeferredHolder.get()` 在注册完成前会抛 `Trying to access unbound value`。家族里的列表/反查索引都要做成懒解析（`MetalFamily.ensureIndex()` 就是这么修的）。
- **效果属性必须用 `addAttributeModifier` 注册**：覆写 `createModifiers` 只影响展示，不会作用到实体上（颤栗当初就是这样"看起来对但没生效"）。NeoForge 提供带等级曲线的重载。
- **`MobEffectEvent.Applicable` 没有实现 ICancellableEvent**（这个版本），不能 `setCanceled`；需要"免疫"就改用定时清理。
- **FakePlayer 对绝大多数伤害源无敌**：测抗性/减免要用真实生物（僵尸可以穿盔甲）。
- **物品受伤后的无敌帧会吃掉第二刀**：测"叠加"时必须先 `invulnerableEntity.invulnerableTime = 0`。
- **配方类型的字符串不要跟着物品 id 一起替换**：`raw_sturdygold` 配方的 `type` 是本模组自定义序列化器，改名会报 `Unknown recipe_serializer`。
- **不要用 `Get-Content`/`Set-Content` 做文本替换**：会把中文注释变成乱码（本项目已经中过两次）。要么用编辑工具，要么 `[System.IO.File]::ReadAllText/WriteAllText` 配 `UTF8Encoding($false)`，并注意文件是 CRLF。
- **写文件一律不要 BOM**：`Set-Content -Encoding UTF8` 会带 BOM，JSON 与 .java 都可能因此出问题。
- **重跑 runServer 前先清残留 java 进程并删 `run/world/session.lock`**：否则新进程会因为世界被占用而失败，日志看起来像是"没生效"。
- **不要强杀 Gradle 进程**：会写坏配置缓存，报 `Could not load compiled classes for build file`，修法是 `gradlew --stop` 后删 `.gradle/configuration-cache`。
