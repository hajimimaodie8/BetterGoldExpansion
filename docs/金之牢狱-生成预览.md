### 1.3 dump 方法

1. `findNearestMapStructure(..., 100, false)` 拿到 start chunk；
2. `level.getChunk(cx, cz, ChunkStatus.FULL, true)` **同步**生成（不调 `setChunkForced`，收尾强制加载区为空）；
3. `level.structureManager().getStructureAt(pos, structure)` 逐 y 找有效 `StructureStart`；
4. `StructureStart#getPieces()` 取 `PoolElementStructurePiece`，读 template / rotation / origin / bbox；
5. 从模板 `filterBlocks(..., Blocks.JIGSAW)` 读 42 个口的绝对坐标 + `name/target/pool`，按“口贴口”配对，BFS 建树；
6. 对件 union 外扩 3 格的 `dumpBox` 逐格 `getBlockState`，写 `blocks.tsv`（120,181 条非空气）；
7. 另切两条剖面（穿过结构方块最多的 `x=600` / `z=732`）逐格 dump。

### 2.3 `start_pool` 为什么保证宝藏房唯一

`start.json` 里**只有一个元素**（`treasure`，权重 1），而且 `fallback = minecraft:empty`。
引擎每次生成只从 `start_pool` roll **一次**得起点 ⇒ 一次生成里 `treasure` 必然恰好 1 个。
本座实测 `treasure = 1 / 18 件`，`[gpx] piece #0 tpl=treasure`。

> ⚠ **第三轮（2026-10-20）就地标注**：上面是**机制**（只保证"起点从 start 池取一次"），
> **不是**「结构上不可能违反」的证明 —— 把 treasure 塞进别的池、或让某个 `fallback` 指向 start，
> 抽样仍可能偶然还是 1 座。本轮已升级为 4 条静态断言
> `[bgp-treasure-unique-start/-noref/-fallback/-nbt]`（15 个池逐文件扫描 + fallback 链遍历 +
> `treasure.nbt` 逐文件引用计数），并用扰动 P10/P11/P12 证明每条都能红；
> 见 `docs\金之牢狱-实现记录.md` **§10.1**。

### 2.4 `lane` 的 `fallback=exit` 怎么生效（本座有 3 次直接证据）

引擎在 `JigsawPlacement` 里对每个口算 `depth+1`；当 `depth+1 > size` 时**不再 roll 目标池**，而是取目标池的 `fallback` 元素。
本座三处：

- `#12 cell_small_fertile`（深度 6）南口 `name=cell_small_3, target=lane, pool=lane` → 深度 7 超限 ⇒ 取 `lane` 池的 fallback = `exit` ⇒ `#15 exit`；
- `#13 cell_large_mirror`（深度 6）西口 `target=lane` ⇒ `#16 exit`；
- `#14 cell_small_fertile`（深度 6）东口 `target=lane` ⇒ `#17 exit`。

所以三条分支**末端都恰好一个出入口**，且都在深度 7。日志 `[gpx] BFS depths = [0,1,2,3,3,3,4,4,4,5,5,5,6,6,6,7,7,7]`。

### 2.5 `size=6` 怎么截断

`size` 是 `max_depth=6`，BFS 深度 0..6 正常 roll；深度 7 只允许 fallback 元素。
本座：宝藏(0) → 过道(1) → 四面道(2) → 3 条过道(3) → 房间(4) → 过道/镜像(5) → 丰饶/大牢房(6) → **出入口(7)**。
没有深度 8 的件；也没有“断头”（34/34 口成对）。

> ⚠ **第四轮（2026-10-21）就地标注**：`cell_small_1→2→3` **硬循环已删除**（= 一图「固定类型」的根因），
> 现行小牢房也进 `room` 池随机；本节只作历史留档。见 §13.2。

### 2.6 小牢房三步循环（`cell_small_1→2→3→lane`）

接线来自 `gp_build.py` 的注口表 + 池文件：

- `cell_small_a` 两个口：`name=cell_small_1, target=cell_small_2, pool=cell_small_2`
- `cell_small_mirror`：`name=cell_small_2, target=cell_small_3, pool=cell_small_3`
- `cell_small_fertile`：`name=cell_small_3, target=lane, pool=lane`

本座走了**两次完整三步**（南分支、东分支）：

- 南：`#6 cell_small_a → #9 cell_small_mirror → #12 cell_small_fertile → #15 exit`
- 东：`#8 cell_small_a → #11 cell_small_mirror → #14 cell_small_fertile → #17 exit`

西分支是 `#7 cell_small_b → #10 lane → #13 cell_large_mirror → #16 exit`（`room` 池 roll 到 `cell_small_b`，没有再走小牢房链）。
三个小牢房池的 `fallback` 都指向**自己**，所以即使 `size` 在链中间截断，下一步也不会断头（本座没触发）。

### 2.7 四面道 4 口如何分叉

`cross_a` 的 4 个口都是 `name=room, target=lane, pool=lane`（`gp_build.py` 注口表 + `cross_a.nbt`）。
本座 `#2 cross_a`（`clockwise_90`）：

- 北口 `(602,41,712)` 被 `#1 lane` 接上（入口）；
- 东口 `(620,41,730)` → `#5 lane`；
- 西口 `(584,41,730)` → `#4 lane`；
- 南口 `(602,41,748)` → `#3 lane`。

**3 个自由口各自独立展开成一条分支**，所以这一座是 1→3 分叉，而不是单链。

### 2.8 `bury` 与 `31..41`

- `terrain_adaptation=bury`：结构埋在地形里；`StructureStart` 盒比件 union **外扩 12 格**（实测 `519..673 / 26..59 / 676..801` vs union `531..661 / 38..47 / 688..789`）。

- 宝藏房“自动低 2 格”在本座成立：`treasure_minY=38`，其余件 `minY=40`，差 2；jigsaw 口全在 y=41。
