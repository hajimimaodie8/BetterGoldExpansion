## 一、实际口径（机理，含量源码行）

原版「装满」判定在 `CrossbowItem#releaseUsing`：

```
i = getUseDuration(stack, entity) - timeLeft;
f = getPowerForTime(i, stack, entity) = i / CrossbowItem.getChargeDuration(stack, entity);   // 要求 f >= 1.0F
```

`CrossbowItem.getChargeDuration` 是 **static**（`CrossbowItem.java:257-260`，基础 `1.25F × 20 = **25**`）
⇒ **它压根不读本模组覆写的 `getUseDuration`**。

| 量 | 值 | 谁在读它 |
|---|---|---|
| 原版 static 分母 | **25 tick** | **装载门槛**（`releaseUsing` 里的 `f >= 1.0F`） |
| 本模组 `getUseDuration` | `chargeDuration(...) + 3` = **23** | 只决定「**举着的时长上限**」（超过 23 tick 后物品不再是"使用中"） |
| 本模组 `chargeDuration(...)`（= `CROSSBOW_CHARGE_SECONDS` 1.0 s × 20 = 20） | 20 | 只被 `getUseDuration` 与**客户端拉弓谓词分母**用到（`client/MetalWeaponItemProperties.java:143-154`） |

⇒ `f_max = 23 / 25 = 0.92 < 1`，按住 23 tick 装不上；玩家按住超过 `getUseDuration` 之后
`useItemRemaining` 转负、松手时 `i = 实际按住的 tick 数` ⇒ **真正装满需要 ≥ 25 tick**。
**A 级**（真玩家按住右键 40 tick、逐 tick 采样）：`chargeDuration=20 useDuration=23 vanillaChargeDuration=25`；
按住期间 `CHARGED_PROJECTILES` 恒空（`charged=false`，`useItemRemaining` 22 → −14），**松手那一 tick `charged=true`**
（`docs/bg16-证据/10-A级-runClient读数.txt`、`docs/bg16-证据/12-新发现-真问题.md` §二）。

## 五、诚实边界

- **代码逻辑没变** ⇒ 手感与第三轮实测一致：**按住 ≥ 25 tick 松手才装填**（比规格写的慢 5 tick = 0.25 s）。

  `runClient` 的按住/松手 A 级用例）。
- 本轮**未跑** `runClient`：B 项没有引入任何新的运行期行为（只改注释与文档），
  故没有新的 A 级读数；支撑它的 A 级证据仍是第三轮那份（`docs/bg16-证据/10`）。
- 关卡 `[bg16-crossbow-caliber-doc15/16]` 会**主动**拦住"把规格里那句更正删掉"的动作——
  若将来真按 20 tick 做了实现，必须**同时**改这三条（含文档），否则关卡会红（这是设计意图，不是误报）。
