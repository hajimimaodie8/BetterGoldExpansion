## 四、mixin **确实加载了**的日志证据（本轮的静默坑）

第一版把 `CrossbowChargeDurationMixin` 写进 `bettergold.mixins.json` 的 **`"common"`** 键 ⇒ Sponge Mixin **不认识这个键**、
整条被静默忽略：编译全绿、`runData` 全绿、`required: true` 也不报错，而 A 级实测里
`CrossbowItem.getChargeDuration(本模组弩)` 仍然是 **25**（6 条 FAIL）。

改成 **`"mixins"`** 键之后，同一份探针 **33 PASS / 0 FAIL**，并且日志里出现了这一行（**这就是"加载了"的唯一判据**）：

```
[20:04:14] [pool-9-thread-1/DEBUG] [mixin/]: Mixing CrossbowChargeDurationMixin from bettergold.mixins.json into net.minecraft.world.item.CrossbowItem
```

⇒ 关卡把"类名必须在 `mixins` 列表里、且**不在** `client` / `server` 里"钉成断言
（`bg16-crossbow-mixin-listed` / `bg16-crossbow-mixin-side`），扰动用例 **X5b** 专门复现"写成 `common`"这个形状（必红）。

## 五、诚实边界（本轮没做 / 没验）

1. **`gradlew build` 未单独重跑**（见第一节注）；`build` 与已跑的三段是同一批任务。
2. **权威 `i` 的取法**依赖"释放包在实体 `updateUsingItem` 之前被处理"这一顺序：
   本轮 12/12 用例里它与客户端逐 tick 观察值**逐个相等**，但**没有**做包级日志取证（没在
   `ServerGamePacketListenerImpl#handlePlayerAction` 打计数）——若将来这里出现 ±1 的争议，先补那一条。
3. **本模组那条 `pull` 谓词未被钳位**：`i = 21/22` 时读到 **1.05 / 1.10**（>1）。模型 override 判据是"≥ 1.0"，
   所以行为正确；本轮**按派单范围不修**（不在四件事里）。
4. **第一轮客户端探针（mixin 未加载那一版）的两个 vanilla 用例**（`vanilla_t22/t23`）的"权威 i"读数分别是 15 / 30，
   与客户端 `i` 不符（探针自己的服务端捕获在用例切换边界上取样偏了）；**第二轮（修好之后）12 个用例的权威 i 与客户端 i 全部相等**，
   本节所有结论都取第二轮。第一轮日志整份留档（`build/bg17-rc-run1.out`）作为"mixin 未加载"的负向对照。
5. **未跑 `runServer` 之外的世界行为回归**：本轮只验了任务 1/2 的 A 级（仙人掌核心材料 + 弩 19/20），
   上一轮那 42 条世界行为断言**未重跑**（本轮没有触碰那些路径）。
