一、读数本身纠正的两条「判据口径」（不是模组 bug，但下次别再按老口径验）

1. **本版 Patchouli 没有「每页 isErrored()」这个东西** `【读 jar：javap】`
   - `BookPage` / `PageWithText` / `PageDoubleRecipe` / `PageSpotlight` 的成员里**都没有** `isErrored()`；
     `isErrored()` 全仓只出现在 `BookContents`（整本书级）、`GuiBookLanding`、`ItemModBook`、`BookCrashHandler`。
   - 配方页解析失败的**真实信号**是两条：① `PageDoubleRecipe.recipe1/recipe2` 为 `null`
     ② `PageDoubleRecipeRegistry#loadRecipe` 打一条
     `PatchouliAPI.LOGGER.warn("Recipe {} (of type {}) not found", id, type)` —— 是 **WARN，不是 ERROR**。
   - ⇒ 任务书里「★ 每页是否 isErrored()」这条判据换成上面两条；本轮按新口径验：
     **68 条配方引用全部 `recipe1/recipe2 != null`，日志 0 条 `Recipe ... not found`**。
   - 另注：`PageSpotlight` 一个图标槽，失败形态是 `stacks` 为空数组/首元素空栈；本轮 8 个 spotlight 页全部非空
     （栈数 1 / 3 / 4 / 11，与资产的 item 列表长度逐一对上）。

2. **整合服务端的「存档目录名」不能用 `getWorldPath(LevelResource.ROOT).getFileName()` 取** `【实测，本机 dev】`
   - 本机 1.21.1 dev 整合服务端上它返回 **`.`**（第一次跑测就因此被自己的闸门 halt 掉，白跑一轮）。
   - 能用的两条：① `overworld().getLevelData()` 反射 `getLevelName()`（= level.dat 的 LevelName）；
     ② 反射 `MinecraftServer#storageSource`（protected）调 `LevelStorageAccess#getLevelId()`。
   - 本轮读数：`HVWORLD levelName=bgn10hvgen levelId=bgn10hvcw root=…\run\saves\bgn10hvcw` —— 三条互相印证。
