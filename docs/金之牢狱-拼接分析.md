## 0. 结论先行（先看这 8 条）

1. **zip 里不是 `.nbt` 预制件包，而是一个 1.21.1 世界存档**（`LevelName=金之牢狱`，`DataVersion=3955`）。没有 `generated/`、没有 `.nbt`、没有 template_pool / structure / structure_set 的 JSON。→ 任务书里「逐件读 NBT 模板」的前提**不成立**，本档改为**从存档方块反解 14 个件**。
2. **14 个件全部找到**，且每一件旁边都有自己的结构方块（`mode=save`）框着；结构方块的 **BE 数据被留在了负坐标区**（那里方块已被清空，只剩孤立 BE）——正好把 14 个件的**尺寸**留给了我们。
3. **全仓 0 个 `minecraft:jigsaw` 方块**。所以「拼接方向」不能从 jigsaw 的 `orientation/name/target/pool/joint` 读——素材里根本没有这些字段。拼接只能从**几何开口**反推。
4. 但几何出奇地规整：**所有接口都是 3 宽 × 3 高、位于件的中轴、洞口底 = 可行走面**。因此拼接规则可以写成一条**对齐公式**（§4.2），并用 4 个算例逐坐标验证（§4.3）。
5. **牌子→件**的映射已破译：牌子放在每件**东边缘那一列、往南 1 格**（`x = 件x + 宽 − 1`，`z = 件z + 深`）。14 件对应 7 块牌子，语义与尺寸完全自洽（§3.2）。
6. **口述的「三种不同种类」在素材里只有 1 种**：1/2/3 号牢房各 3 份，去掉装饰（金矿/锁链/箱子/刷怪笼）后**逐格 0 差异**。即 **14 个件 = 8 种设计**（宝藏 1 + 四面 2 + 牢房道 3 + 出入口 1 + 过道 1）。这是本轮最重要的「与口述对不上」。
7. **战利品表只有 1 个 sheet、1 个池**（权重 /84），且「无 75/80」与 84 分母**不自洽**；没有「抢夺」列；「5-10X / 1X」两列只有一半填了。→ 无法按作者口述的三处宝箱分池，必须问（§5）。
8. **推荐落法**（§4.6–4.8）：`start_pool = 宝藏房`（天然唯一）→ 过道/牢房道交替 → 末端 `fallback = 出入口`（每条道一个，天然唯一）。宝藏房作为起点自动**低 2 格**（因为它的 jigsaw 局部 y=3，别人是 1）——「埋得比较深」不需要额外字段，是几何自带的。

## 3. 14 个件逐件解析（②）

### 3.1 件在哪、怎么配对的

正坐标区的 14 个件按**尺寸 + 位置**与 14 个结构方块一一配对：

- 12 个大件：件坐标 = 负坐标区域 + (512, 0, 512)，每件西北角有 `structure_block(mode=save)` 方块。
- 两个 5 宽件：P13 在 `(3,−60,501)`（5×5×3），P14 在 `(3,−60,507)`（5×8×5）；两个结构方块在 `(2,−61,500)` / `(2,−61,506)`。

> ⚠ 因为 5 宽件的结构方块**没有 BE**，配对只能靠「尺寸 + 紧邻位置」。**P13/P14 的角色（过道/出入口）由尺寸决定**：
> 5×5×3 = 过道（3 深、5 高），5×8×5 = 出入口（5 深、8 高，带金栅栏门 + 屋顶装饰）。这一点在 §3.4 有内容佐证。

要点：

- **除宝藏房外，所有洞口都是 3 宽 × 3 高，底边都在 `dy=1`**（`dy` 相对件底面 y0）。洞底 = 可行走面的顶面，走进去不用跳。宝藏房是唯一例外：`dy 3–5`。
- 15 / 37 宽件的洞口都**居中**（居中列 `c = (宽−1)/2`：15→7、37→18、5→2、21→10）。

### 4.2 对齐公式（用坐标算，不凭感觉）

设父件 A 的原点 `(xA,yA,zA)`、尺寸 `(sxA,syA,szA)`，它的接口在局部 `(cx,cy,cz)`、朝外方向 `D`；
子件 B 的接口在局部 `(c′x,c′y,c′z)`（B 的这个口朝 `−D`）。原版 `JigsawPlacement` 的做法是：
**把 B 的接口格对齐到 A 接口格的前方一格**，即

```
B.origin = A.origin + (cx,cy,cz) + D − (c′x,c′y,c′z)
```

展开成四个方向（都要求两个口同 `dy`）：

| A 的接口 | D | 子件 B 的接口 | 结果 |
|---|---|---|---|
| 南面（`cz = szA−1`） | `(0,0,+1)` | B 北面（`c′z = 0`） | `xB = xA + cx − c′x`，`yB = yA + cy − c′y`，**`zB0 = zA + szA`** |
| 北面（`cz = 0`） | `(0,0,−1)` | B 南面（`c′z = szB−1`） | `xB = xA + cx − c′x`，`yB = yA + cy − c′y`，**`zB0 = zA − szB`** |
| 东面（`cx = sxA−1`） | `(+1,0,0)` | B 西面（`c′x = 0`） | **`xB = xA + sxA`**，`yB = yA + cy − c′y`，`zB0 = zA + cz − c′z` |
| 西面（`cx = 0`） | `(−1,0,0)` | B 东面（`c′x = sxB−1`） | **`xB = xA − sxB`**，`yB = yA + cy − c′y`，`zB0 = zA + cz − c′z` |

**这就是「B 的 (0,·,·) 对齐到 A 的 (W−1,·,·)、再沿朝向外移 1 格」的准确形式**：
A 的南面最后一层是 `zA+szA−1`，B 的北面第一层正好落在 `zA+szA`，两个面**贴合、不重叠**。
（任务书里那句「再沿朝向外移 1 格」= 子件的接口格落在父件接口格的**前方那一格**，等价。）

`y` 的加减不是特例：**`yB = yA + cy − c′y` 自动处理一切高度差**。
宝藏房的接口 `cy=3`、别人的 `c′y=1` ⇒ 宝藏房做子件时**自动低 2 格**，不需要写任何特判。

### 4.3 逐对几何验证（4 个算例，全部用真实坐标）

> 下面把「父件 A + 子件 B」按公式算出 B 的原点，并核对：面贴合、中轴对齐、走道同高、无重叠。

**算例 1：15 宽牢房道（A）→ 5 宽过道（B）**
A = P04 原点 `(461,−60,413)`，南接口 `(7,1,30)` ⇒ 世界 `(468,−59,443)`，D = south。
B = P13 过道，北接口 `(2,1,0)`。
`xB = 468 − 2 = 466`；`yB = −59 − 1 = −60`；`zB0 = 443 + 1 − 0 = 444`。
⇒ B 占 `x 466–470 / y −60…−56 / z 444–446`。
核对：B 的接口 `(468,−59,444)` 贴着 A 的 `(468,−59,443)` ✓；B 中轴 468 = A 中轴 468 ✓；走道 dy1–3 同高 ✓；A 的南最后一层 z=443、B 的北第一层 z=444，**不重叠** ✓。

**算例 2：5 宽过道（A）→ 15 宽牢房道（B）**
A = P13 原点 `(466,−60,444)`，南接口 `(2,1,2)` ⇒ 世界 `(468,−59,446)`。
B = P07 2 号牢房，北接口 `(7,1,0)`。
`xB = 468 − 7 = 461`；`yB = −59 − 1 = −60`；`zB0 = 446 + 1 = 447`。
⇒ B 占 `x 461–475 / z 447–467`。中轴 468 ✓，面贴合 ✓。
（有趣的是这正好等于世上 P05 的坐标 `(461,−60,447)`——作者把 3 号牢房摆在了 461 那一列，间距 3 格；**这不是证据，只是巧合**，别当拼接实例。）

**算例 3：37 宽四面道（A）→ 15 宽牢房道（B），走东口**
A = P02 原点 `(421,−60,435)`，东接口 `(36,1,18)` ⇒ 世界 `(457,−59,453)`，D = east。
B = P07，西接口 `(0,1,10)`。
`xB = 457 + 1 − 0 = 458`；`yB = −59 − 1 = −60`；`zB0 = 453 − 10 = 443`。
⇒ B 占 `x 458–472 / z 443–463`，走道中心 z = 453 = A 东口中轴 ✓，y 同高 ✓，A 东最后一层 x=457、B 西第一层 x=458 ✓。

**算例 4：15 宽牢房道（A）→ 宝藏房（B），走 A 的北口（宝藏房在 A 北边）**
A = P10 原点 `(497,−60,473)`，北接口 `(7,1,0)` ⇒ 世界 `(504,−59,473)`，D = north。
B = P01 宝藏房，南接口 `(10,3,20)`。
`xB = 504 − 10 = 494`；`yB = −59 − 3 = −62`；`zB0 = 473 − 1 − 20 = 452`。
⇒ B 占 `x 494–514 / y −62…−54 / z 452–472`。
核对：B 的接口 `(504,−59,472)` 贴着 A 的 `(504,−59,473)` ✓；B 中轴 504 = A 中轴 504 ✓；**B 整体比 A 低 2 格**（y −62 vs −60）⇒ 宝藏房「沉下去 2 格」= 埋得更深 ✓✓；B 的可行走面 `y=−59` 与 A 的 `y=−59` **同高**（沉的是壳体，不是地面）✓。

> 算例 4 是整份文档最关键的一条：**「埋得比较深」不用额外字段，是宝藏房接口 `dy=3` 自然产生的 −2 偏移。**

### 4.4 几何等价的「target → 可用件」表

如果下一轮真的要加 jigsaw（推荐），按下面的 socket 命名就能**强制「房间 ↔ 过道」交替**，
并用 pool 的 `fallback` 做终端：

| 父件接口的 `target` | 能接上的子件 `name` | 可用件 |
|---|---|---|
| `bettergold:prison/lane` | `bettergold:prison/lane` | **过道 P13**、**出入口 P14**（终端） |
| `bettergold:prison/room` | `bettergold:prison/room` | **1/2/3 号牢房**、**四面道 A/B**、**宝藏房 P01**（终端） |

- 牢房道 / 四面道的接口：`name = prison/room`、`target = prison/lane`。
- 过道 P13 的接口：`name = prison/lane`、`target = prison/room`。
- 宝藏房 P01 的接口：`name = prison/room`、`target = prison/lane`（它只接一个过道；若做 `start_pool`，就从它的南口向外展开）。
- 出入口 P14 的接口：`name = prison/lane`、`target = prison/room`（终端，不再展开）。

> 这套命名满足原版 `JigsawBlock.canAttach` 的硬条件：
> ① 两个 front 必须相对（`direction == other.getOpposite()`）；
> ② `joint=aligned` 时 top 必须相同（这里全 `up`，天然满足）；
> ③ **父件的 `target` 必须逐字等于子件的 `name`**（单向匹配，不是双向）。
> 源码：`JigsawBlock.canAttach`（本档证据目录 `src_JigsawBlock.java`）。

**为什么要交替**：任务书里作者原话「一条小道的话架构差不多就是房间加过道」。
用上面两个 socket 名，**房间只能接过道、过道只能接房间**，模型上就强制了「房间 + 过道」的节奏，
且 5 宽过道只能落在 15/37 宽房间的 3 宽洞口上（中轴对齐）——几何上也不会错位。

### 4.5 ★ 「到临界点换成出入口」：3 个方案对比

先把原版行为钉死（**源码**，`JigsawPlacement.tryPlacingChildren`，行号见 `src_JigsawPlacement.java`）：

- `:313` 每个件的 jigsaw 点是 **`getShuffledJigsawBlocks` 随机打乱**的；
- `:350` **`if (depth != maxDepth)`** 才把主池放进候选，否则**只用 fallback 池**；
- `:354` `list.addAll(holder1.value().getShuffledTemplates())` —— fallback 不是「失败才用」，而是**候选列表的第二段**；
- `:359-485` 按候选顺序逐个试，**第一个能 attach 的就放**；
- `:474` `if (depth + 1 <= this.maxDepth)` 才继续展开 ⇒ 到 `maxDepth` 还能再放**一个**件，但那个件不再展开。
- `:401` 能不能接由 `JigsawBlock.canAttach` 决定（front 相对 + top 相同 + `target==name`）。

⇒ 原版**没有**「数到第 N 件就换成某件」的机制。`depth` 是**每个分支的连接深度**，不是全局件数。
所以「到临界点换出入口」只能靠 **fallback 池 + 深度上限** 来近似，或写 Java。

| 方案 | 做法 | 能否做到「只在末端出现出入口」 | 局限 |
|---|---|---|---|
| **(a) start_pool = 出入口 + 中段池 + `size` 卡长度** | `start_pool=出入口`，`size=N`。出入口在**起点** | **能**（起点唯一，且就是末端之一） | 出入口在「入口端」而不是「远端」；如果链分叉，只有起点 1 个出入口，其余分支末端没有 |
| **(b) 出入口放进中段池 + `projection` / fallback 约束** | 出入口和过道同池、靠权重随机 | **不能** | 权重是**每次连接独立 roll**，位置完全随机；`projection` 只管 y 贴地，不管「第几件」 |
| **(c) 自定义 `StructurePiece` / `StructureType`** | 自己数「已放件数」，到 N 换成出入口；或自己决定每个连接点放什么 | **能，且能精确控制** | 最重：要写 Java、注册 `StructureType`、自己处理包围盒/碰撞/`StructureTemplate` 放置；本仓有 Java 能力，可行但工作量最大 |

**本档推荐的落地形态（(a)+(b) 的组合，见 §4.6）**：
`start_pool = 宝藏房`（一个终端件当根），中段「过道 ↔ 牢房道」交替，**过道池的 `fallback = [出入口]`**（另一个终端件当叶）。
在一条**不分叉**的链上，`size=N` 时最后一个过道槽位必然用 fallback ⇒ **末端恰好 1 个出入口**，
且它**占的正是过道的槽位**（宽度 5、接口 3×3 完全一致）——这就是作者说的「顶掉过道的位置」。

> ⚠ **分叉就会破**：四面道 4 个口都接 jigsaw 的话，每个分支都会各自走到 `maxDepth`，
> 每个分支末端都会放一个出入口 / 一个宝藏房。所以「只生成一个宝藏房」和「四面道四通」**在纯 jigsaw 下互斥**。
> 这是本轮必须让作者拍板的第四号问题（§7 Q4）。

### 4.6 ★ 「宝藏房只生成一个」：4 个方案

| 方案 | 做法 | 为什么能/不能保证唯一 | 代价 |
|---|---|---|---|
| **A（推荐）宝藏房做 `start_pool`** | `start_pool = [宝藏房]`，它向南长出道 | **天然唯一**：`JigsawPlacement.addPieces` 每次生成只 `getRandomTemplate` **一次**起点（`:74`），起点只有一个 | 宝藏房在「根」，不是「末端」；但它本来就只有 1 个口，做根很自然 |
| B 线性链 + 末端 `fallback = [宝藏房]` | 中段池 `fallback` 指向单件池 | **只有链不分叉时**唯一；分叉 ⇒ 每个末端一个 | 依赖「每件只有 1 个前进口」 |
| C 独立 `structure_set` 单件池 | 宝藏房单独成一个结构，`spacing/separation` 拉大 | **能**唯一（一个结构实例只有一个起点） | 与地牢**不相连**；要另做「入口如何进去」 |
| D 自定义 `StructurePiece` 计数 | 全局计数到 1 后不再放 | **能**精确 | 最重 |

**为什么「池里只放 1 件」不够**：BFS 是**每个连接点独立**去池里 roll（`:350`、`:359`），
池里 1 件只是让「每次 roll 都是它」，不是「全局只放 1 次」。所以「单件池 + `size` 上限」**不能**保证唯一。

**推荐 A 的连带好处**：
- 宝藏房是根 ⇒ 它的 `start_height` 就是整座结构的基准深度，**「只会生成一个」是构造保证**，不靠概率。
- 宝藏房的接口 `dy=3` 让它的孩子（第一条过道）自动 `y+2` ⇒ **宝藏房比整条链低 2 格**，「埋得比较深」自洽（§4.8）。
- 出口（出入口）仍可用「过道池 fallback = [出入口]」放在每条**分支**末端；作者没说出入口只能 1 个，多分支多出入口是合理的。

### 4.7 「埋得比较深」怎么表达

有 **3 个层次**，建议同时用前两个：

1. **整座结构的深度**：`structure` 的 `"start_height"`（`HeightProvider`）。下界维度高度是 **0…255**（`dimension_type/the_nether.json`: `min_y=0`, `height=256`），
   所以**不能用 −40 这种下界坐标**。建议 `{"type":"minecraft:uniform","min_inclusive":{"absolute":18},"max_inclusive":{"absolute":26}}`
   （层 18–26，低于下界熔岩海 y≈31，被下界岩包住）。
2. **件自身的下沉**：宝藏房接口 `dy=3` vs 别人 `dy=1` ⇒ 作为子件时**自动 y−2**；作为 `start_pool` 时，
   它的孩子自动 `y+2`，等价于「宝藏房比链低 2」。**这是几何自带的，不需要写字段**（§4.3 算例 4）。
3. **地形包裹**：`"terrain_adaptation": "bury"`（枚举值见 `TerrainAdjustment.java`：`none/bury/beard_thin/beard_box/encapsulate`）。
   `bury` 会在结构外再包一层地形，视觉上「埋进去」。⚠ 它会把整座结构包住，入口可能需要另外挖开——**要不要用 `bury` 需要作者确认**。
4. （可选）`"projection": "rigid"`（pool element 字段）：所有件刚性跟随起点的 y，不做地形贴合 ⇒ 保持「一整条平的道」。
   若要各件按地形贴地，用 `"terrain_matching"`，但那样宝藏房的 −2 偏移会被地形抹掉，**不建议**。

> 「宝藏房只生成一个 / 末端只有一个出入口」就不再成立（分叉后每个分支都会走到 `depth==maxDepth`）。
> 要严格唯一，二选一：①四面道只保留 **北/南** 两个 jigsaw（东/西口当装饰，不接）；②把四面道从 `prison/room` 里拿掉，只留 1/2/3 号。

`size=8`（偶数）⇒ 深度 8 的那件是「房间」，它的 `target=lane` 走到 `prison/lane` 池，`depth==maxDepth` 时只用 fallback ⇒ 放**出入口**。
（深度 0=宝藏、1=过道、2=房间、3=过道… 偶数=房间。**奇偶必须对齐**，否则末端会拿错池的 fallback。）

> ⚠ 还有一个原版细节：`depth != maxDepth` 时 fallback **也在候选里**（`:354` 把主池和 fallback 拼成一个列表），
> 只是排在主池后面。所以若某次主池的件全都放不下（碰撞/越界），**终端件可能提前出现**。
> 空旷的主世界/下界里很少见；如果作者要求「严格只在最后一个」，那就是 §4.5 方案 (c)。

### 5.2 复算：这张表用的是哪套公式

- 28 个物品行的权重合计 = `7 + 5×4 + 4×2 + 3×8 + 2×10 + 1×3` = **82**；分母 84 ⇒ **「无」的等效权重 = 2**。
- 概率列 = `1 − (1 − w/84)^7.5`：金粒 `1−(1−7/84)^7.5 = 47.9%`（表 47.35%）、金锭 `36.9%`（表 36.54%）、
  `w=1` 的 `8.6%`（表 8.57%）——**吻合**（差 0.3–0.5 个百分点，应是取整/7.5 的近似）。
- 物品数列 = `7.5 × w/84 × 平均堆叠`：金粒 `7.5×7/84×10.5 = 6.56` ✓、金锭 `3.57` ✓、金钱贝 `0.89` ✓。
  ⇒ **rolls = 5…10（均值 7.5）**，权重分母 84，**「无」占 2/84**。
- ⚠ **对不上的 3 行**：金苹果（算 0.80，表 1.88）、金蛋（算 0.80，表 2.14）、金胡萝卜（算 0.80，表 0.54）。
  这三行的「物品数」与「权重×堆叠」不一致，**表内自相矛盾**。
- ⚠ **「无 75/80」与 84 分母不自洽**：93.75% 既不是 `2/84`（2.4%），也不是 `1−(1−2/84)^7.5`（16.7%）。
  它更像另一版「75/80 空、5/80 出货」的 1 次 roll 设计残留。**这一格必须问作者**。
