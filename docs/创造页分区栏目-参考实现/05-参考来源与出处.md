## §1 参考实现是谁

| 项 | 值 |
|---|---|
| 名称 | Simulated Project（Create: Aeronautics 系列） |
| 仓库 | `Creators-of-Aeronautics/Simulated-Project` |
| 分支 | `main` |
| 抓取日期 | 2026-09（本文档写作时复核过：`data.jsdelivr.com` 的 flat 清单 692,465 字节，与本地缓存逐字节等长） |
| 相关包 | `dev.simulated_team.simulated`（多模块：`simulated/`、`aeronautics/`、`offroad/`，各有 `common/` 与 `neoforge/` 子模块） |

**它的整体思路（一句话）**：用 Mixin **独占**自己的那个 `CreativeModeTab`，
在 `buildContents` 里把私有 `displayItems` 换成自建列表（可以含 `ItemStack.EMPTY`），
再用另一个 Mixin 在自己页被选中时、在 `render` 的 TAIL 上画横幅。

### 2.5 数据文件（分区定义的存放位置）

| 路径 | 内容 |
|---|---|
| `simulated/common/src/main/resources/assets/simulated/simulated/sections/simulated.json` | 示例分区定义（264 字节） |
| `aeronautics/common/src/main/resources/assets/aeronautics/simulated/sections/aeronautics.json` | 同上的另一个命名空间（211 字节） |
| `offroad/common/src/main/resources/assets/offroad/simulated/sections/offroad.json` | 同上（261 字节） |

**目录规则**：因为 `SimpleResourceManager.create(codec, path)` 把目录拼成
`path.getNamespace() + "/" + path.getPath()`，而 `Simulated.path("sections")` = `simulated:sections`，
所以实际目录是 **`assets/<任意命名空间>/simulated/sections/*.json`** —— 别的模组可以用**自己的命名空间**
往同一个标签页里加分区（跨模组兼容的设计）。

示例 `simulated.json` 的内容（**极短片段引用，仅用于说明字段名**，来源见 `LICENSE.md` 的许可说明）：

```json
{
  "priority": 0,
  "title": {
    "text": { "translate": "simulated.simulated_section.simulated" },
    "background": "#aa39231c",
    "color": "#ffffeb8c",
    "secondary_color": "#ffcea05a"
  },
  "sprite": "simulated:banner",
  "only_animate_on_hover": true
}
```

从这段可以看到三个值得借鉴的设计点：**分区顺序用 `priority` 而非代码枚举**、
**释词是 `Component`（可翻译）**、**背景/主色/副色都由数据给出**。
注意 `"sprite": "simulated:banner"` 指向的是 **`textures/gui/sprites/banner.png`**（进 GUI 图集的那一份），
仓库里另有一份 `textures/gui/banner/*.png` 是不进图集的 —— 这正是 `02` §2 的互证材料。

## §3 可复现的抓取命令

### 3.1 环境限制（重要）

本机环境里 **`github.com` / `api.github.com` / `raw.githubusercontent.com` 都解析不到公网** 【记录：环境既有结论】，
所以 `git clone` 与 GitHub API 都用不了。**jsDelivr 通道可用**，用它替代：

> 本文档写作时**实际验证过的是 jsDelivr 的两个端点**（`data.jsdelivr.com/.../flat` 与
> `cdn.jsdelivr.net/gh/...` 均返回 HTTP 200）；「GitHub 域名不可达」是环境既有结论，本轮未重复验证。

| 用途 | URL 形式 |
|---|---|
| 取文件清单（平铺） | `https://data.jsdelivr.com/v1/package/gh/Creators-of-Aeronautics/Simulated-Project@main/flat` |
| 取文件清单（目录树，含目录项） | `https://data.jsdelivr.com/v1/package/gh/Creators-of-Aeronautics/Simulated-Project@main/tree` |
| 取单个文件 | `https://cdn.jsdelivr.net/gh/Creators-of-Aeronautics/Simulated-Project@main/<仓库内路径>` |

**两个已知限制**

1. **清单会漏文件**（实测：`CreativeModeInventoryScreenSelectedTabAccessor.java` 在两个清单里都没有，
   但 CDN 直取正常）。所以清单只用来找线索。
2. jsDelivr 对 GitHub 仓库有缓存与体积限制；拿不到时换 `@<commit sha>` 或稍后重试。

### 3.2 照抄的命令（PowerShell）

```powershell
$repo = 'Creators-of-Aeronautics/Simulated-Project'
$ref  = 'main'
$base = "https://cdn.jsdelivr.net/gh/$repo@$ref/"
$tmp  = Join-Path $env:TEMP 'aero-src'
New-Item -ItemType Directory -Force -Path $tmp | Out-Null

# ① 文件清单（平铺）；本机实测 692,465 字节
Invoke-WebRequest "https://data.jsdelivr.com/v1/package/gh/$repo@$ref/flat" `
    -OutFile (Join-Path $tmp 'flat.json') -UseBasicParsing

# ② 在清单里找与分区/横幅相关的文件
$j = Get-Content (Join-Path $tmp 'flat.json') -Raw -Encoding utf8 | ConvertFrom-Json
$j.files | Where-Object { $_.name -match 'creative_tab_sections|simulated_tab|SimTabService|client/sections|simulated/sections' } |
    Select-Object name, size | Format-Table -AutoSize

# ③ 取单个文件（注意：路径要与清单里的一致，斜杠原样保留）
$f = 'simulated/common/src/main/java/dev/simulated_team/simulated/registrate/simulated_tab/SimulatedCreativeTab.java'
Invoke-WebRequest ($base + $f) -OutFile (Join-Path $tmp 'SimulatedCreativeTab.java') -UseBasicParsing
Select-String (Join-Path $tmp 'SimulatedCreativeTab.java') -Pattern 'SECTION_Y_VALUES|padMenuItems|renderBanners|blitSprite'

# ④ 确认「清单里没有、但说不定存在」的路径（本例应当 200）
Invoke-WebRequest ($base + 'simulated/common/src/main/java/dev/simulated_team/simulated/mixin/accessor/CreativeModeInventoryScreenSelectedTabAccessor.java') `
    -UseBasicParsing | Select-Object StatusCode, @{n='len';e={$_.Content.Length}}
```

**只看不下载**：`flat.json` 用编辑器打开搜 `creative_tab_sections` 即可；
单个文件也可以直接在浏览器里打开 CDN 链接。

### 4.3 原版客户端资源（核对 GUI 图集定义与物品格偏移）

```powershell
$jar = "$env:USERPROFILE\.gradle\caches\neoformruntime\artifacts\minecraft_1.21.1_client.jar"
# 取出 assets/minecraft/atlases/gui.json —— 内容只有一条 directory 源 gui/sprites
```

```json

```

**物品格「8 / 17」偏移的像素级核实**（本文档写作时新查证）：CATEGORY 类页的背景是
`assets/minecraft/textures/gui/container/creative_inventory/tab_items.png`（256×256；取得方式同上，
把 `atlases/gui.json` 换成该路径即可）。读它的像素：

```powershell
Add-Type -AssemblyName System.Drawing
$bmp = New-Object System.Drawing.Bitmap("$env:TEMP\tab_items.png")
# 第一格的上/左边框与内部
(8..26)  | ForEach-Object { "y17 x={0}: {1:X8}" -f $_, $bmp.GetPixel($_, 17).ToArgb() }
(14..22) | ForEach-Object { "x8  y={0}: {1:X8}" -f $_, $bmp.GetPixel(8, $_).ToArgb() }
```

观察结果（十六进制 RGB）：

```
y=17: x=8..24 = #373737（上边框）  x=25 = #8B8B8B  x=26 = #373737（下一格的左边框）
y=18: x=8 = #373737（左边框）  x=9..24 = #8B8B8B（格内）  x=25 = #FFFFFF（右边框高光）
```

⇒ 第一格 = `x 8..25`、`y 17..34`（18×18，周期 18），格内 16×16 从 `(9, 18)` 开始 ——
正好等于槽位坐标 `9 + 列*18, 18 + 行*18`（`CreativeModeInventoryScreen.java:1010`）。
**这就是物品区左上角 = `(leftPos + 8, topPos + 17)` 的由来**（`【像素实测】`）。

## §6 我们自己的 NeoForge 版范例（建议优先看这些）
