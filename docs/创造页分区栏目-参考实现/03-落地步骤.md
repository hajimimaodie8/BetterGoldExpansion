# 03 - 落地步骤（NeoForge 1.21.1）

> **本文档解决什么问题：** 给出可照着做的实现顺序和关键代码骨架 —— 注册分区标签页、按分区投放物品、
> 客户端画横幅、把行号映射到屏幕坐标、资源放哪。**骨架不是整文件**，只给关键片段，方便移植到你的包名/命名。
> **适合谁看：** 直接动手写代码的人。前置：NeoForge 1.21.1（本文档按 21.1.228 校对）、会用 `DeferredRegister`、
> 不需要 Mixin。原理与算法细节见 `01-原理与数据结构.md`，踩坑见 `02-关键坑与对策.md`。

## 步骤 1：先定分区表（数据结构，不写渲染）

**要做的事**：把「这一页有哪些分区、顺序如何、每区怎么判定」写成一个 `List<Slot>`。这一步做完，
横幅顺序和释词就**已经被决定**了，后面所有代码都只是执行者。

```java
/** 一个分区：横幅上的释词 + 归属判定 */
public record Slot(String title, Predicate<ItemStack> test) {}

/** 材料页：其他材料 → 交易金商人相关 → 金属 */
public static final List<Slot> MATERIALS = List.of(
        // 注意：兜底判定必须放最后；这里的第一个分区是「正面判定」而不是 stack -> true
        new Slot("其他材料",       s -> !isTraderRelated(s) && !isMetal(s)),
        new Slot("交易金商人相关", CreativeTabSections::isTraderRelated),
        new Slot("金属",           CreativeTabSections::isMetal));
```

**纪律（会直接决定成败）**

- `Slot` 列表的**顺序就是横幅顺序**；
- 兜底（`stack -> true`）**只能出现在最后一位**（否则后面的分区全空，见 `01` §2）；
- 释词在一页内**必须唯一**（它是 `SECTION_ROWS` 的 key 的一部分，重复会互相覆盖）。

**判定条件要规则驱动，不要枚举物品**：靠物品注册名（`BuiltInRegistries.ITEM.getKey(stack.getItem()).getPath()`）
的后缀/前缀判定。完整后缀表见 `01` §7。

**验收点**：这一步不需要跑游戏。但请先在心里（或纸上）过一遍：随便挑 3 个你的物品，
它们分别落在哪个分区？有没有任何物品会「谁都不要」？（有也会被最后一个分区兜住，但要确认那是不是你想要的）

## 步骤 2：候选物品从哪来

**要做的事**：给每一页准备一个候选物品列表（`List<ItemStack>`）。两种常见来源：

```java
/** 来源 A：直接遍历你自己的注册表（保持注册顺序） */
private static List<ItemStack> ownItems(Predicate<ItemStack> filter) {
    List<ItemStack> out = new ArrayList<>();
    for (var holder : MY_ITEMS.getEntries()) {          // DeferredRegister#getEntries
        ItemStack stack = holder.get().getDefaultInstance();   // ← 只能在注册完成之后调用
        if (filter.test(stack)) out.add(stack);
    }
    return out;
}
```

**注意**：候选列表的求值时机必须在**注册完成之后**（`getEntries()` 里的 `get()` 在注册前会抛
`Trying to access unbound value`，见 `02` §3 姊妹坑）。本仓库的做法是把候选收集写成
`Supplier<List<ItemStack>>` 传给 `displayItems` 生成器，**在生成时（注册早已完成）才求值**：

```java
SectionedCreativeTab.builder("materials", MATERIALS, CreativeTabSections::materialsCandidates)
```

**候选列表要「宽松」**：宁可多给（认不出来的会被兜底分区收下），不要漏给。
「一件物品凭空消失」是最难查的 bug；「物品在错的横幅下面」一眼就能看出并修规则。

## 步骤 3：排布 —— `layout()` 与 `SECTION_ROWS`

把分区结果（`List<Bucket>`）排成「物品 + 空行」，并记录每个分区的首物品行。**完整实现与推导见 `01` §5**，
这里是骨架：

```java
public static final int ITEMS_PER_ROW = 9;

/** key = "标签页key|释词"，value = 该分区【首个物品】所在行（0 基）。横幅行 = 值 − 1 */
public static final Map<String, Integer> SECTION_ROWS = new LinkedHashMap<>();

public static List<ItemStack> layout(String tabKey, List<Bucket> buckets) {
    List<ItemStack> out = new ArrayList<>();
    SECTION_ROWS.keySet().removeIf(k -> k.startsWith(tabKey + "|"));

    for (int i = 0; i < ITEMS_PER_ROW; i++) out.add(ItemStack.EMPTY);   // ← 开头补一整行（勿删）

    for (int b = 0; b < buckets.size(); b++) {
        Bucket bucket = buckets.get(b);
        SECTION_ROWS.put(tabKey + "|" + bucket.title(), out.size() / ITEMS_PER_ROW);  // ← 取样在加物品【之前】
        out.addAll(bucket.items());
        if (b == buckets.size() - 1) break;                            // ← 最后一区不补
        int used = bucket.items().size() % ITEMS_PER_ROW;
        int pad = (ITEMS_PER_ROW - used) % ITEMS_PER_ROW + ITEMS_PER_ROW;  // 补满当前行 + 再空一整行
        for (int i = 0; i < pad; i++) out.add(ItemStack.EMPTY);
    }
    return out;
}
```

**三个不能改的地方**（改了就会出观感 bug）：① 开头补一整行；② 取样在加物品之前；③ `pad` 一定 ≥ 9。

**验收点**：写完后立刻用 `01` §9 的不变量 I6（`R_{b+1} == ceil((R_b*9 + n_b)/9) + 1`）在心里验一遍，
或者等步骤 9 用探针打出来。**不要**用「长度 % 9 == 0」当断言（最后一区不补，长度一般不是 9 的倍数）。

## 步骤 4：会补空行的标签页 —— `withTabFactory` + 覆写 `getDisplayItems()`

**为什么要这么做**：`output.accept(ItemStack.EMPTY)` 会抛异常（`02` §1），所以生成器里**只放非空格子**，
空行在 `getDisplayItems()` 里补。这个做法之所以成立，是因为 NeoForge 提供了官方扩展点
`CreativeModeTab.Builder#withTabFactory`，让你决定**造哪个 `CreativeModeTab` 子类**。

**扩展点的源码依据（【读源码】`CreativeModeTab.java`）**

```java
// 第 212 行：默认工厂就是 CreativeModeTab::new
private java.util.function.Function<CreativeModeTab.Builder, CreativeModeTab> tabFactory = CreativeModeTab::new;

// 第 315-318 行
public CreativeModeTab.Builder withTabFactory(java.util.function.Function<CreativeModeTab.Builder, CreativeModeTab> tabFactory) {
    this.tabFactory = tabFactory;
    return this;
}

// 第 365 行（build() 内）
CreativeModeTab creativemodetab = tabFactory.apply(this);
```

即：**N 个公开 API 就搞定了子类替换**，不需要 Mixin、AccessTransformer 或反射。

**骨架**

```java
public final class SectionedCreativeTab extends CreativeModeTab {

    private final Layout layout;

    private SectionedCreativeTab(CreativeModeTab.Builder builder, Layout layout) {
        super(builder);                       // ← 必须调父类构造器（它读 builder 里的全部字段）
        this.layout = layout;
    }

    /** 给注册代码用的工厂：一次配好「生成器 + 子类」 */
    public static CreativeModeTab.Builder builder(String tabKey, List<Slot> slots, Supplier<List<ItemStack>> candidates) {
        Layout layout = new Layout(tabKey, slots);
        return CreativeModeTab.builder()
                .displayItems((parameters, output) -> layout.build(candidates.get(), output))
                .withTabFactory(builder -> new SectionedCreativeTab(builder, layout));
    }

    /** 创造界面就是从这里取物品列表的 → 在这里把空行补回去 */
    @Override
    public Collection<ItemStack> getDisplayItems() {
        return this.layout.padded(super.getDisplayItems());
    }

    /** 生成器与渲染之间的桥梁 */
    private static final class Layout {
        private final String tabKey;
        private final List<Slot> slots;
        private volatile List<Bucket> buckets = List.of();      // 最近一次构建的分区结果

        void build(List<ItemStack> candidates, CreativeModeTab.Output output) {
            List<Bucket> grouped = buckets(this.slots, candidates);
            List<ItemStack> laidOut = CreativeSections.layout(this.tabKey, grouped);  // 顺带记录 SECTION_ROWS
            for (ItemStack stack : laidOut) {
                if (!stack.isEmpty()) output.accept(stack);     // ← 空格子一个都不 accept
            }
            this.buckets = grouped;
        }

        Collection<ItemStack> padded(Collection<ItemStack> source) {
            List<Bucket> grouped = this.buckets;
            if (grouped.isEmpty()) return source;               // 还没构建过 → 原样返回
            List<ItemStack> flat = List.copyOf(source);
            int expected = 0;
            for (Bucket b : grouped) expected += b.items().size();
            if (expected != flat.size()) return flat;           // ← 长度守衡：宁可不画，也不能错位
            // 只按长度切片重建 Bucket，物品本身以原版集合为准
            ...
            return CreativeSections.layout(this.tabKey, rebuilt);
        }
    }
}
```

**四个容易写错的细节**

1. `super(builder)`：`CreativeModeTab` 的构造器签名是 `protected CreativeModeTab(Builder)`，
   **子类必须把 builder 原样传进去**（`CreativeModeTab.java:76` 会把 builder 的字段全部读出来）。
2. `getDisplayItems()` **每次调用都会执行一遍 `padded`** —— 原版在切页、切搜索页时都会调它。
   所以 `padded` 必须是纯函数、无副作用，且要能接受「`buckets` 还空着」（第一次调用可能早于生成器）。
3. **长度守卫不能省**（见上）。有别的模组往你的页里插物品时，退回「不加空行」是唯一安全的反应。
4. `displayItems` 生成器**只调用一次**吗？不一定。原版可能在资源重载时重建（`tryRebuildTabContents`）。
   所以 `buckets` 用 `volatile` 并整块替换，而不是增量修改。

## 步骤 5：注册标签页 + 排序链

```java
public static final DeferredRegister<CreativeModeTab> CREATIVE_MODE_TABS =
        DeferredRegister.create(Registries.CREATIVE_MODE_TAB, MODID);

public static final DeferredHolder<CreativeModeTab, CreativeModeTab> MATERIALS_TAB =
        CREATIVE_MODE_TABS.register("bettergold_materials_tab", () ->
                SectionedCreativeTab.builder("materials", CreativeTabSections.MATERIALS,
                                CreativeTabSections::materialsCandidates)
                        .title(Component.translatable("itemGroup.bettergold_materials"))
                        .icon(() -> AllItems.STURDYGOLD_INGOT.get().getDefaultInstance())
                        // 语义：withTabsBefore(X) = X 在本页之前 → 本页排在刷怪蛋页【之后】
                        .withTabsBefore(CreativeModeTabs.SPAWN_EGGS)
                        // 页与页之间串成一条链
                        .withTabsAfter(ResourceLocation.fromNamespaceAndPath(MODID, "bettergold_tab"))
                        .build());
```

并在 mod 构造器里 `CREATIVE_MODE_TABS.register(modEventBus);`

**排序纪律（详见 `02` §5）**

- 记法：`withTabsBefore(X)` = **X 在本页之前**；`withTabsAfter(X)` = **X 在本页之后**；
- 整条链锚在 `CreativeModeTabs.SPAWN_EGGS`（普通原版页的第 10 个）之后；
- **绝不要**锚 `CreativeModeTabs.HOTBAR / SEARCH / OP_BLOCKS / INVENTORY` —— 它们是
  `CreativeModeTabRegistry.DEFAULT_TABS`，被排除在排序图的**节点**之外，但排序用的**边**没有排除它们，
  Guava 的 `putEdge` 会把它们自动补成节点，于是原版页被拉进排序、跑到奇怪的位置；
- 每一页都至少要有一条 `withTabsBefore` 或 `withTabsAfter`，不要依赖「没写就连在最后」那条分支。

**验收点**：跑一次 `runServer`，打印 `CreativeModeTabs.tabs()`，确认自己的页都排在 `spawn_eggs` 之后、
顺序与你写的链一致（做法见 `04` §2）。这一步**不要**跳过，排序错了后面看渲染会白费功夫。

## 步骤 6：客户端渲染钩子

**挂在哪**：NeoForge 的 `ScreenEvent.Render.Post`。它由
`ClientHooks#drawScreenInternal` 在 `screen.renderWithTooltip(...)` **之后**立刻发出
（【读源码】`ClientHooks.java:427-430`）：

```java
private static void drawScreenInternal(Screen screen, GuiGraphics guiGraphics, int mouseX, int mouseY, float partialTick) {
    ...
    screen.renderWithTooltip(guiGraphics, mouseX, mouseY, partialTick);
    NeoForge.EVENT_BUS.post(new ScreenEvent.Render.Post(screen, guiGraphics, mouseX, mouseY, partialTick));  // 第 430 行
}
```

⇒ 此时物品格底板、物品、滚动条都已经画完，**你在事件里画的东西在最上层**，不会被后续绘制盖掉。
（参考实现用的是 `@Inject(method = "render", at = @At("TAIL"))`，时序等价。）

```java
@EventBusSubscriber(modid = MODID, value = Dist.CLIENT)
public final class CreativeSectionBanners {

    private static final int ITEM_AREA_X = 8;    // 相对 leftPos
    private static final int ITEM_AREA_Y = 17;   // 相对 topPos
    private static final int CELL = 18;
    private static final int ITEMS_PER_ROW = 9;
    private static final int VISIBLE_ROWS = 5;
    private static final int BANNER_WIDTH = 162;   // 9 × 18
    private static final int BANNER_HEIGHT = 18;

    @SubscribeEvent
    public static void onScreenRender(ScreenEvent.Render.Post event) {
        if (!(event.getScreen() instanceof CreativeModeInventoryScreen screen)) return;

        ResourceLocation tabId = selectedTabId();                 // 反射读静态字段 selectedTab
        if (tabId == null) return;
        Page page = pageOf(tabId);                                // 你的「页 → 横幅贴图」映射
        if (page == null) return;

        var rows = CreativeSections.SECTION_ROWS;
        if (rows.isEmpty()) return;

        var menu = screen.getMenu();                              // CreativeModeInventoryScreen.ItemPickerMenu
        int firstVisibleRow = firstVisibleRow(menu, scrollOffs(screen));
        int left = guiLeft(screen) + ITEM_AREA_X;
        int top  = guiTop(screen)  + ITEM_AREA_Y;
        GuiGraphics graphics = event.getGuiGraphics();

        for (var entry : rows.entrySet()) {
            String key = entry.getKey();
            int sep = key.indexOf('|');
            if (sep < 0 || !sameTab(key.substring(0, sep), page, tabId)) continue;
            int row = bannerRow(menu, entry.getValue() - firstVisibleRow);   // 自适应判定，见步骤 7
            if (row < 0) continue;
            drawBanner(graphics, page.banner(), key.substring(sep + 1), left, top + row * CELL);
        }
    }
}
```

**反射要读的四个东西**（字段都是 private，只能反射；位置见 `02` §6）：

```java

    Field f = findField(screen.getClass(), "scrollOffs");
    ...
}
```

**反射的三条纪律**

1. **失败必须静默降级**：拿不到字段就不画横幅，**绝不能因为装饰性渲染把客户端搞崩**。
   所有 `ReflectiveOperationException` 都要 catch 并忽略（最坏的结果是「没横幅」，而不是崩溃）。
2. `leftPos` / `topPos` 声明在**父类** `AbstractContainerScreen` 上（第 74/78 行），
   反射要找**整条继承链**；找不到就用 NeoForge 暴露的 `screen.getGuiLeft()/getGuiTop()`（第 752-753 行）兜底。
3. **不要在每帧做字符串拼接/查表**到令人不安的程度 —— 这个事件每帧触发，
   但分区数量是个位数，字典序很小的循环完全无感。真正的性能坑是 `blitSprite` 查图集失败（`02` §2），不是这里。

**必须做的前置判断（顺序不要变）**

1. 是创造界面吗？（`instanceof CreativeModeInventoryScreen`）
2. 选中的是本模组的页吗？（反射读 `selectedTab` + 命名空间判断）
3. 本页有分区记录吗？（`SECTION_ROWS` 非空且前缀匹配）

少任何一步，就会在别人的页上画出你的横幅。

## 步骤 7：把 `SECTION_ROWS` 映射到屏幕坐标

**三个算式，一个都不能错。**

```
① 首个可见行（照抄原版 ItemPickerMenu#getRowIndexForScroll，第 1033-1035 行）
   rowCount = max(ceil(items.size() / 9) - 5, 0)
   firstVisibleRow = max((int)(scrollOffs * rowCount + 0.5), 0)

② 记录值 → 可见行
   anchor = SECTION_ROWS.get(key) - firstVisibleRow      // 记录值记的是「首物品行」
           （减完之后 0..4 才是可见行；<0 或 >4 就是不画）

③ 可见行 → 屏幕坐标
   x = leftPos + 8
   y = topPos + 17 + row * 18
```

```java
private static int firstVisibleRow(ItemPickerMenu menu, float scrollOffs) {
    int rowCount = Mth.positiveCeilDiv(menu.items.size(), ITEMS_PER_ROW) - VISIBLE_ROWS;
    if (rowCount <= 0) return 0;                       // ← 不满 5 行时不能除/乘出负数
    return Math.max((int) ((double) (scrollOffs * (float) rowCount) + 0.5), 0);
}
```

**然后做自适应判定**（`02` §4）：不要直接 `y = topPos + 17 + (记录值 − 1 − firstVisibleRow) * 18`，
而是「目标行整行空就画那里，否则看上一行，都不空就不画」：

```java
private static int bannerRow(ItemPickerMenu menu, int anchor) {
    if (isRowEmpty(menu, anchor))     return anchor;
    if (isRowEmpty(menu, anchor - 1)) return anchor - 1;
    return -1;
}
private static boolean isRowEmpty(ItemPickerMenu menu, int row) {
    if (row < 0 || row >= VISIBLE_ROWS) return false;
    int first = row * ITEMS_PER_ROW;
    if (first + ITEMS_PER_ROW > menu.slots.size()) return false;
    for (int i = first; i < first + ITEMS_PER_ROW; i++)
        if (menu.getSlot(i).hasItem()) return false;
    return true;
}
```

**`8 / 17 / 18` 这几个数字是哪来的（【读源码】+【像素实测】）**

- 物品槽按 9 列 × 5 行注册，坐标是 `9 + 列*18, 18 + 行*18`（`CreativeModeInventoryScreen.java:1010`）。
  这个坐标是**物品（16×16）**的绘制位置：`AbstractContainerScreen#renderSlot` 取 `int i = slot.x; int j = slot.y;`
  然后 `renderItem(itemstack, i, j, ...)`（`AbstractContainerScreen.java:244-246`、`299-304`）。
- 而**格子底图是 18×18**，左上角比物品坐标各少 1 像素 —— 这不是推算，是**像素级核实的**：
  CATEGORY 类页用的背景是 `assets/minecraft/textures/gui/container/creative_inventory/tab_items.png`
  （256×256），把它从客户端 jar 里取出来看像素，第一格是：

  ```
  y=17: x=8..24 = #373737（上边框）   x=25 = #8B8B8B    x=26 = #373737（下一格的左边框）
  y=18: x=8 = #373737（左边框）  x=9..24 = #8B8B8B（格子内部）  x=25 = #FFFFFF（右边框高光）
  ```

  ⇒ 第一格占 `x = 8..25`、`y = 17..34`（**正好 18×18**），周期 18；格子内部 16×16 从 `(9, 18)` 开始，
  正好是槽位坐标 —— 与物品绘制位置严丝合缝。
  取像素的命令见 `05-参考来源与出处.md` §4.3。
- 所以**物品区（= 一整格栅格）左上角 = `(leftPos + 8, topPos + 17)`**；一格 = 18 像素，
  横幅宽 = 9 × 18 = 162、高 = 18 —— 正好铺满一整行。

**绘制顺序（与参考实现一致）**：① 先 blit 横幅底图 → ② 在横幅左端画释词底方块（半透明填充）
→ ③ 最后写释词文字。

```java
private static void drawBanner(GuiGraphics g, ResourceLocation banner, String title, int x, int y) {
    g.blit(banner, x, y, 0, 0.0F, 0.0F, BANNER_WIDTH, BANNER_HEIGHT, BANNER_WIDTH, BANNER_HEIGHT);
    Font font = Minecraft.getInstance().font;
    Component text = Component.literal(title);
    int w = font.width(text);
    g.fill(x + 3, y + 3, x + w + 3 + 5 + 3, y + BANNER_HEIGHT - 3, 0x90000000);  // 释词底方块
    g.drawString(font, text, x + 5, y + 5, 0xFFFFFFFF, true);                     // true = 带阴影
}
```

**如果横幅贴图不是 162×18**（例如为了高清做了 324×36）：`blit` 的后两个参数是**贴图实际尺寸**，
前两个是**绘制尺寸**，写反会导致贴图被裁剪或拉伸：

```java
g.blit(banner, x, y, 0, 0F, 0F, /*绘制宽*/162, /*绘制高*/18, /*贴图宽*/324, /*贴图高*/36);
```

释词文字建议用 `Component.translatable("你的语言键")`，而不是 `Component.literal("中文")` —— 否则无法本地化。

## 步骤 8：资源目录放法

**横幅贴图（用 `blit`，推荐）**

```
src/main/resources/assets/<你的命名空间>/textures/gui/creative_sections/materials.png
                                                                        blocks.png
                                                                        gear.png   ...
```

代码里的 `ResourceLocation`：

```java
// 注意：ResourceLocation 里的路径要带 textures/ 前缀和 .png 后缀
ResourceLocation.fromNamespaceAndPath(MODID, "textures/gui/creative_sections/materials.png");
```

**横幅贴图（用 `blitSprite`）**

```
src/main/resources/assets/<你的命名空间>/textures/gui/sprites/banner.png      （+ 可选 banner.png.mcmeta）
```

代码里是 `ResourceLocation.fromNamespaceAndPath(MODID, "banner")` —— **去掉 `textures/`、`gui/sprites/` 前缀与 `.png`**。
万一查不到，图集不会报错而是返回 missing sprite（紫黑格），排查方法见 `02` §2。

**文案**：释词如果用 `Component.translatable(...)`，记得在
`assets/<ns>/lang/zh_cn.json` 与 `en_us.json` 里加键，否则玩家看到的是原始键名。

**参考实现的资源布局可以互证**（【读源码】+ jsDelivr 文件清单，见 `05` §2）：
Aeronautics 同时存在 `textures/gui/banner/*.png`（未进图集）与 `textures/gui/sprites/banner.png`（进图集），
而它实际 `blitSprite` 引用的是后者。

## 步骤 9：从零到跑起来的顺序（建议照做）

| 阶段 | 做什么 | 怎么确认（不要跳过） |
|---|---|---|
| 1 | 分区声明 + 排序规则（步骤 1~2） | 编译通过即可 |
| 2 | `layout()` + `SECTION_ROWS`（步骤 3~4） | 写一个**纯 JVM 单元测试**或用 `runServer` 探针，验 I3（不丢物品）与 I6（行号算术）；此时还不用看画面 |
| 3 | 注册 + 排序链（步骤 5） | `runServer` 打印 `CreativeModeTabs.tabs()`，确认位置对（`04` §2） |
| 4 | 客户端渲染骨架：只画一个**纯色矩形**（`graphics.fill`）在第一个分区的横幅行 | `runClient` 打开创造模式，确认**位置对、跟随滚动**。这一步用纯色能最快定位「是坐标算错了还是贴图路径错了」 |
| 5 | 换成真正的横幅贴图 + 释词 | `runClient` 人眼确认（`04` §6） |
| 6 | 收尾：删掉所有探针、grep 确认无残留、`gradlew build` | grep 探针标记（例：`TEMP-`、`PROBE`），确认零命中；见 `02` §7 探针纪律 |

**为什么第 4 阶段要用纯色矩形**：横幅不出现有三种完全不同的原因 —— 坐标错、贴图路径错（静默紫黑格）、
条件没进。用 `graphics.fill` 先排除坐标问题，能省掉大量猜测。这是本仓库走过弯路后总结的顺序。

## 附：常见改造点

| 想改成 | 改哪里 |
|---|---|
| 分区之间不留空行（只做间隔感） | 改 `layout()` 的 `pad`（例如去掉 `+ ITEMS_PER_ROW`）；**必须同时**把渲染端的自适应判定保留（它找不到空行就不会画，横幅随之消失） |
| 横幅改成 2 格高 | 资源高 36，`BANNER_HEIGHT = 36`；`layout()` 的 `pad` 改成 `(9-used)%9 + 18`（空两行）；`isRowEmpty` 要改成「连续两行都空」 |
| 每个分区用不同的横幅贴图 | 你的「分区 → 横幅」映射。本仓库 1.4 定稿：**一页 5 个分区**，`SECTION_ROWS` 的键就是分区 key，渲染端拿 key 去 `CreativePageSections.byKey(key)` 取该分区的横幅与释词（早前按页分图的 `pageOf(ResourceLocation tabId)` 已随「5 页合并成 1 页」删除） |
| 物品 tooltip 里显示分区名 | 在 `ItemTooltipEvent` 或原版 `getTooltipFromContainerItem` 的注入里按「物品 → 分区」反查；分区名与 `SECTION_ROWS` 的 key 同源 |
| 一个物品想出现在两个分区 | **不行**。原版的 `accept` 会对重复 stack 抛异常，`layout` 的切片也假定每件物品只出现一次 |
